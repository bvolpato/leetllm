# Manual review notes: GPU Serving & Autoscaling

Reviewed September 22, 2026. Read the complete original article, metadata, all thirteen original marked CPU examples, ten quiz questions, twenty-five citation records, original generated notes, all eight native illustration sources, and banner. Read the final edits directly. Relevant upstream selections are listed below; this isn't a claim to have read every complete project or paper.

- [vLLM metrics](https://docs.vllm.ai/en/stable/design/metrics/): current V1 names and the latency definitions. `inter_token_latency_seconds` samples output-event gaps, including bundled outputs; `request_time_per_output_token_seconds` samples completed requests. At-most-one-token completions export zero TPOT, whereas the serving benchmark excludes them. The new two-event exercise demonstrates why 40 ms and 13.3 ms can describe the same stream without revealing individual token gaps.
- [vLLM LLM API](https://docs.vllm.ai/en/stable/api/vllm/entrypoints/llm/): inspected chat signature and default chat-template behavior. Changed the unexecuted GPU sketch to `llm.chat` so the instruction template is actually applied. [Optimization](https://docs.vllm.ai/en/stable/configuration/optimization/): inspected current chunked-prefill scheduling, token-budget tradeoffs, and preemption context.
- [Qwen3.6-27B card](https://huggingface.co/Qwen/Qwen3.6-27B) and [full config](https://huggingface.co/Qwen/Qwen3.6-27B/raw/main/config.json): 27B language component plus vision encoder; language-only serving mode; 64 language layers, 48 linear and 16 full attention; full-attention KV heads/dimension and FP32 recurrent matrix layout. The 65.3 GB worksheet is explicitly a language-component lower bound, not a full artifact payload or measured fit. Loaded vision/prediction modules and convolution/runtime state need additional accounting.
- [TensorRT-LLM migration](https://nvidia.github.io/TensorRT-LLM/latest/legacy/tensorrt-backend-removal.html): current migration section inspected; PyTorch is the sole execution backend and the separate legacy engine-build step was removed. Retained the version-qualified engine comparison and corrected the contradictory cold-start mitigation. [TGI](https://huggingface.co/docs/text-generation-inference/index): inspected maintenance-mode notice; no new TGI deployment recommendation.
- [KEDA 2.20 concepts](https://keda.sh/docs/2.20/concepts/scaling-deployments/) and [ScaledObject spec](https://keda.sh/docs/2.20/reference/scaledobject-spec/): activation versus HPA phases and cooldown-to-zero scope. Followed the obsolete 2.19 page's latest link and verified upstream latest release [v2.20.2](https://github.com/kedacore/keda/releases/tag/v2.20.2), published July 31, 2026. Refreshed the article and versioned citation. This controller is a teaching policy, not HPA or a measured heterogeneous capacity estimator.
- [Kubernetes HPA](https://kubernetes.io/docs/concepts/workloads/autoscaling/horizontal-pod-autoscale/), [probes](https://kubernetes.io/docs/concepts/workloads/pods/probes/), and [Karpenter concepts](https://karpenter.sh/docs/concepts/): inspected downscale stabilization/default scale-up behavior, startup/readiness/liveness differences, and unschedulable-pod node provisioning. Placement is separate from loaded, warmed readiness.
- [Dynamo disaggregated serving](https://docs.nvidia.com/dynamo/dev/knowledge-base/concepts/system-architecture/disaggregated-serving): inspected prefill/decode ownership, KV-aware routing, backend-specific metadata, NIXL transfer, runtime worker drain, and mixed-iteration chunk tradeoffs. Splitting phases still needs state compatibility, cancellation, and bounded pressure.
- [MIG supported products](https://docs.nvidia.com/datacenter/tesla/mig-user-guide/supported-gpus.html): checked A100/H100/H200 support and maximum seven instances on listed products. [GKE image streaming](https://docs.cloud.google.com/kubernetes-engine/docs/how-to/image-streaming): inspected remote-filesystem/background-cache mechanism and startup limitations. [FSx for Lustre](https://docs.aws.amazon.com/fsx/latest/LustreGuide/what-is.html): inspected shared POSIX filesystem and EC2/EKS access. No storage throughput or cold-start duration here is a measured result.
- [vLLM LoRA](https://docs.vllm.ai/en/stable/features/lora/) and [prefix cache design](https://docs.vllm.ai/en/stable/design/prefix_caching/): inspected SupportsLoRA/per-request API and cache-salt isolation. Runtime adapter loading isn't tenant authorization. Warmup must match the eventual eligible prefix/adapter/isolation identity; an unrelated salt doesn't warm another namespace.

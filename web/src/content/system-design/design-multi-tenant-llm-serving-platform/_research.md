## Checked primary selections

- [OWASP authorization](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html): read deny-by-default and every-request permission selections. Authentication and caller-selected workspace identity aren't authorization; the worker and cache still need resolved authority.
- [PostgreSQL transaction isolation](https://www.postgresql.org/docs/current/transaction-iso.html): read isolation/background, repeatable-read retry, and relevant serializable anomaly/commit/rollback selections. Serializable transactions can abort and need retries of the transaction. Committed database state must govern dispatch; a rollback doesn't undo an external GPU side effect. No SQL or distributed transaction was executed.
- [PostgreSQL row security](https://www.postgresql.org/docs/current/ddl-rowsecurity.html): checked enabled-policy/default-deny, whole-table-operation exclusions, role bypass, owner/FORCE behavior, and policy combination selections. Ordinary roles differ from superusers/BYPASSRLS and table owners. The deployed retrieval role must be checked rather than assuming policies constrain it. This isn't a complete RLS/security-definer audit.
- [vLLM current optimization](https://docs.vllm.ai/en/latest/configuration/optimization/): read preemption/chunked-prefill and token-budget tuning selections. max_num_batched_tokens is an iteration budget, not tenant quota or a latency guarantee. Decode prioritization and prefill chunking still need a measured workload and explicit overload policy; example settings aren't prescriptions.
- [vLLM LoRA guide](https://docs.vllm.ai/en/stable/features/lora/): read supported-model/per-request adapter use, serving controls, dynamic loading, and trusted-environment warning. Kept immutable authorized revisions, safe reference lifetimes, and protected administrative endpoints. Didn't run loaders, arbitrary paths/URLs, or runtime-update flags.
- [NVIDIA MIG concepts](https://docs.nvidia.com/datacenter/tesla/mig-user-guide/latest/concepts.html): read GPU-instance versus compute-instance and partitioning selections. Compute instances within one GPU instance share memory/engines; separate GPU instances partition resources. The article correctly separates those boundaries from containers, VMs, and host trust. Didn't provision a GPU or verify every hardware profile.
- [vLLM metrics](https://docs.vllm.ai/en/stable/design/metrics/): directly checked output-event ITL, completion-based per-request TPOT, bundled outputs, weighting, and at-most-one-token behavior. The added 100/220/240-ms trace distinguishes a 120-ms event gap from 35-ms TPOT. No event trace reconstructs internal gaps inside a multi-token bundle.
- Reused preceding manual reviews' inspected [PagedAttention](https://arxiv.org/abs/2309.06180), [Orca iteration-level scheduling](https://www.usenix.org/conference/osdi22/presentation/yu), [LoRA](https://arxiv.org/abs/2106.09685), and [vLLM prefix-block identities/salts](https://docs.vllm.ai/en/stable/design/prefix_caching/).

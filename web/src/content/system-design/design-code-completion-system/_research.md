# Code Completion System: manual source notes

Reviewed September 23, 2026. Read the complete original 1,158-line article, metadata, twelve marked CPU exercises, eight questions, eighteen reference records, generated research, all five native sources, and the legacy banner prompt. These hand-written notes replace the generated blueprint and apply only to this bundle.

## Evidence and interface contracts

- [GitHub code-suggestion concepts](https://docs.github.com/en/copilot/concepts/completions/code-suggestions): read inline and next-edit behavior, model-selection scope, and public-code matching selections. Inline ghost text and predicting the location of the next edit are separate interactions; neither establishes one universal latency target.
- [Copilot cloud agent](https://docs.github.com/en/copilot/concepts/agents/cloud-agent/about-cloud-agent): checked repository research, planning, branch/PR work, and Actions execution selections. That workflow has a separate interaction budget from keystroke completion. This isn't a complete product availability or policy audit.
- [Partial acceptance](https://docs.github.com/en/copilot/how-tos/get-code-suggestions/get-ide-code-suggestions#accepting-partial-suggestions): checked word/line acceptance. Editor controls differ. Define any-partial versus full acceptance and count distinct shown suggestion IDs; multiple partial actions on one suggestion aren't multiple shown suggestions.
- [Tree-sitter introduction](https://tree-sitter.github.io/tree-sitter/index.html): read its incremental concrete-syntax-tree and useful-error-recovery description. Recovery doesn't guarantee correct scope, symbol visibility, authorization, or a fixed sub-5-ms runtime.
- [LSP overview](https://microsoft.github.io/language-server-protocol/): checked the editor/language-server separation and feature scope. Didn't newly read the full current protocol or all position-encoding negotiation rules; don't equate every editor/LSP position with one encoding.
- [Pinned VS Code declarations](https://github.com/microsoft/vscode/blob/1fe7285a1162756215a684ee702b16d0ce42bdb4/src/vscode-dts/vscode.d.ts#L269): downloaded the exact source revision and directly read document-version, offsetAt/positionAt, Position, and inline-provider declarations. VS Code positions/offsets use UTF-16 units; versions increase on changes including undo/redo. The provider receives document/position/context/cancellation inputs. The rendered API site didn't expose the relevant declarations through this reader, so the source is the checked evidence. No extension was run.
- [VS Code programmatic language features](https://code.visualstudio.com/api/language-extensions/programmatic-language-features): read completion and inline-provider selections. Multi-token ghost text doesn't make stale application state safe. Paint and acceptance need snapshot/range checks even when obsolete work is cancelled.

## Model and serving evidence

- [Bavarian et al., FIM](https://arxiv.org/abs/2207.14255): checked abstract, format/cache selections, character-versus-token span ablation, and Appendix D's joint SPM encoding. PSM and SPM aren't interchangeable adapter strings. The paper's tested left-to-right preservation and span results don't guarantee every checkpoint. Ordinary instruction-based infill is also possible; the defining native contract is the checkpoint's trained/documented interface.
- [Qwen2.5-Coder report](https://arxiv.org/abs/2409.12186): checked metadata, tokenization, file/repository pretraining, and the PDF's exact Figures 3/4 formats. File FIM sends fim_prefix, prefix, fim_suffix, suffix, fim_middle, then generates middle. Repository markers are separate framing. This 2024 checkpoint is an interface example, not a recommendation for the latest/best model.
- [vLLM prefix-cache design](https://docs.vllm.ai/en/stable/design/prefix_caching/): read block hashing, parent/exact-token identity, extra adapter/multimodal keys, salts, allocation, eviction, and reuse selections. A cache hit needs compatible scope and runtime state; a salt is one component, not an entire isolation policy. Decode isn't removed by a prefix hit. Local tuple fixtures don't store engine KV tensors.
- [Current vLLM speculation guide](https://docs.vllm.ai/en/latest/features/speculative_decoding/): checked method families, workload sensitivity, and losslessness/numerical selections. Proposals can use a learned draft, n-grams, or native multi-token machinery. Speed and first-token effects require compatible measured workloads. Ideal sampling-distribution preservation doesn't guarantee identical hardware floating-point outputs. Didn't execute flags, kernels, or every version-specific configuration.
- [Hugging Face TGI overview](https://huggingface.co/docs/text-generation-inference/en/index): checked continuous batching and maintenance-mode notice. The article already correctly qualifies TGI's status; didn't replace that with an unqualified current-engine recommendation.
- [Transformers GPTQ guide](https://huggingface.co/docs/transformers/main/en/quantization/gptq): read method/backends/loading and compatibility selections. Current development docs use GPTQModel and mark AutoGPTQ unsupported. The article doesn't instruct readers to install AutoGPTQ. A quantized infill candidate still needs checkpoint/kernel/quality validation; no loader or GPU was exercised.
- Reused the preceding manual serving reviews' original [speculative-sampling algorithm](https://arxiv.org/abs/2211.17192), [PagedAttention](https://arxiv.org/abs/2309.06180), [GPTQ](https://arxiv.org/abs/2210.17323), and [HumanEval](https://arxiv.org/abs/2107.03374) mechanisms. No historical aggregate becomes a present performance guarantee.

## Measurement and arithmetic corrections

- [Productivity Assessment of Neural Code Completion](https://arxiv.org/abs/2205.06537): read the original abstract, background, usage/persistence definitions, and survey-method selections. The 27% acceptance figure is early-2022 technical-preview evidence; the unpaid survey population was self-selected. Acceptance correlated more strongly with perceived productivity than persistence measures. Retention in this design is a complementary deletion signal, not proven semantic utility or a causally established replacement. The 2024 CACM page returned HTTP 403, so the precise factual paragraph now cites the inspected 2022 primary paper.
- Added the literal `a😀b` position counterexample: caret offsets are 2 Python indices, 3 UTF-16 units, and 5 UTF-8 bytes. A wrong-unit slice erases the suffix or splits an encoded character. This checks arithmetic, not a general position converter.
- Fixed the fleet sketch's product of averages. The original 52-GPU arithmetic needs equal conditional prompt means (or equivalent independence). With the same 800 req/s, 2,048-token aggregate mean, 50% request hit rate, and 75% skip on hits, longer-hit and longer-miss distributions give 36 and 67 worksheet GPUs. Those counts assume the invented 20,000-token capacity and omit decode, memory, queueing, failures, and headroom.
- Existing full-trace percentile, retained-character, cancellation/freshness, and tenant-key fixtures retain their stated synthetic/local scope. Added a distribution question and position checkpoint rather than a universal recipe. Cache affinity is a preference subject to queueing, not an unconditional warm-shard pin.
- Direct visual/source inspection found the chart helper's default minimum height made zero characters look like a positive bar. Both local charts now request zero minimum height; numeric labels remain visible. No shared helper or other article was rewritten.

Removed generated claims about universal 100-ms limits, fixed parser timings, prescribed model-size cascades, permanently frozen KV blocks, guaranteed speculative speedups, ZDR implying immediate physical purge, ignore-file conventions guaranteeing upload exclusion, mandatory 15-ms debounce, cancellation instantly freeing GPU work, byte slicing equaling token budgeting, and unsupported benchmark/cost comparisons. Broader privacy/logging and upload boundaries remain explicit application contracts.

These checks cover the selections named above, not complete upstream projects, every full paper, all legal/privacy obligations, or a provider/model call. No real editor integration, user experiment, load generator, GPU benchmark, production route change, or deployment was performed.

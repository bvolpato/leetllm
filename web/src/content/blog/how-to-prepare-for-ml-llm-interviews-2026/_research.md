## Core Technical Topics to Prioritize

Build your foundation from stable mechanics upward. Master Tier 1 before chasing 2026's newest architectures.

### Tier 1: Core to Almost Every System

- **Classical ML & Experimentation:** Gradient descent, bias-variance trade-offs, objective choice, and A/B testing are useful role-dependent practice. For next-token prediction, $\mathcal{L}=-\sum_i\log P(x_i\mid x_{<i};\theta)$ sums negative log probabilities of the target tokens given earlier tokens. Reduction and masking determine the implementation's actual scale.
- **Transformer Architecture:** Know the decoder forward pass, Query (Q), Key (K), and Value (V) projections, Rotary Positional Embedding (RoPE), ALiBi, and Pre-LN vs. Post-LN.

- *The Math:* $\operatorname{Attention}(Q,K,V)=\operatorname{softmax}(QK^T/\sqrt{d_k})V$, with softmax over keys and the appropriate mask for the task. Query/key dimension $d_k=64$ gives divisor 8. Scaling reduces the growth of dot-product magnitudes under the paper's variance argument; it does not guarantee that softmax can never saturate. Tokens do not have to correspond one-to-one with words.
- *Primary Source:* Vaswani et al., "Attention Is All You Need" ([https://arxiv.org/abs/1706.03762](https://arxiv.org/abs/1706.03762))
- **Inference Optimization:** Practice KV-cache allocation, batching, and latency on an explicit workload. Four bits are 0.5 bytes per packed weight value, but scales, metadata, unpacked tensors, and KV state add memory beyond that arithmetic. Don't present a theoretical value-size ratio as measured serving savings.

### Tier 2: Common in Production

- **Retrieval-Augmented Generation (RAG):** RAG relies heavily on ingestion, chunking, indexing, retrieval, reranking, and generation. Know your retrieval probes: recall@k, Mean Reciprocal Rank (MRR), and normalized Discounted Cumulative Gain (nDCG).

- *Primary Source:* Lewis et al., "Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks" ([https://arxiv.org/abs/2005.11401](https://arxiv.org/abs/2005.11401))
- **Fine-Tuning & Alignment:** Compare full fine-tuning with parameter-efficient methods like LoRA and QLoRA. Understand instruction tuning, Reinforcement Learning from Human Feedback (RLHF), and Direct Preference Optimization (DPO).

- *Primary Source:* Rafailov et al., "Direct Preference Optimization" ([https://arxiv.org/abs/2305.18290](https://arxiv.org/abs/2305.18290))
- **Agent Architectures:** ReAct loops, Plan-and-Execute, protocol-based tool discovery, and handling hallucinated tool calls or context overflow.
- **Evaluation:** Differentiate between retrieval metrics (recall@k) and generation metrics (exact match, pass@k). Understand LLM-as-judge limits, human inter-annotator agreement, and benchmarks like MMLU and SWE-bench.

### Tier 3: 2026 Advanced Capabilities & Differentiators

Treat these as role-dependent boosters:

- **Tool Integrations:** Model Context Protocol (MCP) for standardized resource exposure ([https://modelcontextprotocol.io](https://modelcontextprotocol.io)).
- **Architectures & Paradigms:** Mixture of Experts (MoE) for sparse routing, speculative decoding, Reinforcement Learning from Verifiable Rewards (RLVR), reasoning models (test-time compute), and hybrid Transformer+SSM architectures like Jamba.

## The SCALE System Design Framework

SCALE is an optional editorial mnemonic, not a documented employer requirement or uniquely established framework. Use it if it helps you make the design's assumptions and evaluation explicit:

1. **S**cenario: Define user experience, latency, budget, and failure cost.
2. **C**omponents: Outline embedding models, vector stores, LLMs, cache, and guardrails.
3. **A**rchitecture: Map out the offline indexing path alongside the online request path.
4. **L**atency & Cost: Establish per-query token budgets, p95 targets, and identify throughput bottlenecks.
5. **E**valuation: Define metrics *before* naming tools. (e.g., "If relevant docs are {doc_B, doc_E} and retrieval returns [doc_A, doc_B, doc_C], Recall@3 is 0.5.")

## Practical Takeaways: Debugging and Problem Solving

### Worked Example: The "Lost in the Middle" Problem

**Scenario:** A RAG system fetches a 50-page incident runbook. The model cites rules from the first and last pages but misses a vital clause on page 25.
**Hypothesis:** Finding a document does not guarantee that the needed clause reached the final prompt. Inspect extraction, selected passages, truncation, and exact submitted context first. The paper supports a position-sensitivity hypothesis on its tested tasks and models.
**Controlled test:** Hold the clause, question, model, and other context fixed while varying evidence position. Compare outputs before adding a reranker or changing retrieval. An improvement supports position sensitivity for that workload, not a guarantee that top/bottom placement solves all errors.

- *Primary Source:* Liu et al., "Lost in the Middle" ([https://arxiv.org/abs/2307.03172](https://arxiv.org/abs/2307.03172))

### The Debugger Challenge

During behavioral or architectural rounds, decompose failures systematically. If an LLM answers with an incorrect date regarding an incident, isolate the components:

| Layer | Possible Failure Mode |
| --- | --- |
| Retrieval | The tool returned the wrong incident ID or a stale database record. |
| Context | The retrieved record was accurate, but the prompt assembly omitted the trusted "current date". |
| Reasoning | Both the record and date were present, but the model hallucinated the chronology. |

**Interview Tip:** A regression test should log retrieved status, supplied date, cited evidence, expected diagnosis, and the observed answer. Every fix must be measurable.

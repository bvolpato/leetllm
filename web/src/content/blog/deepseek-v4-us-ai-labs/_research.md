# DeepSeek V4 and the US AI Lab Squeeze

Your coding agents don't need a premium closed model for every step. Some requests require hard, multi-step reasoning. Many others are routine repo scans, issue summaries, test-log triage, or low-risk codebase Q&A.

DeepSeek V4 matters because it gives engineering teams a cheaper, long-context evaluation lane before every request is routed to the most expensive models. Instead of asking, "Which frontier model should handle this?", teams can now ask: "Which requests belong on V4-Flash, which need V4-Pro, and which still require a premium closed model?"

## What DeepSeek Released

Keep checkpoint evidence separate from the hosted service. The September 10 release retired V4 Flash and Flash Vision Exp API models; their old names temporarily route to V4.1 Flash. V4 Pro remains available after the originally announced September 14 end date. Official lifecycle source: https://api-docs.deepseek.com/updates/.

- **DeepSeek-V4-Pro:** The hard-reasoning lane. It is a 1.6 trillion parameter **mixture-of-experts (MoE)** model, but it only activates 49 billion parameters per token. It supports a 1 million token context window. (Source: `[https://build.nvidia.com/deepseek-ai/deepseek-v4-pro/modelcard](https://build.nvidia.com/deepseek-ai/deepseek-v4-pro/modelcard)`)
- **DeepSeek-V4-Flash:** The faster, routine lane. It is a 284 billion parameter MoE model that activates 13 billion parameters per token, also supporting a 1 million token context window.
- **Mixed Precision:** The V4 report describes FP8 pretraining and FP4 quantization-aware post-training for MoE expert weights, with most other parameters stored in FP8. This describes the V4 target, not the successor V4.1 architecture. Original report: https://arxiv.org/html/2606.19348v1.
- **Packaged size:** The official Flash 0731 and Pro 0813 cards attach DSpark speculative decoding modules to the target. Hub package badges (304B and 1.7T) therefore aren't interchangeable with target counts (284B and 1.6T). Cards: https://huggingface.co/deepseek-ai/DeepSeek-V4-Flash-0731 and https://huggingface.co/deepseek-ai/DeepSeek-V4-Pro-0813.

## Why 1M Context Isn't Just a Bigger Number

A long context window is only useful if the model can afford to keep generating tokens.

During generation, the server maintains a **KV cache**, which stores attention keys and values from prior tokens so the model doesn't have to recompute the whole prefix for every new word. At hundreds of thousands of tokens, memory and bandwidth dominate the system.

Coding agents stress this architecture heavily. A useful agent carries instructions, file contents, stack traces, failed patches, and prior decisions in its prompt. If long context is too computationally expensive, the system is forced to aggressively truncate or retrieve before the model sees enough raw evidence.

### The Hybrid Attention Solution

DeepSeek V4's core technical achievement is hybrid attention. The model card details **Compressed Sparse Attention (CSA)** and **Heavily Compressed Attention (HCA)**.

The V4 report estimates Pro at 1M context uses 27% of V3.2's single-token equivalent-FP8 FLOPs and 10% of its accumulated KV cache. These architecture estimates aren't measured request latency or independent throughput benchmarks. CSA compresses 4:1 and selects compressed entries; HCA compresses 128:1 and attends over the compressed representation. Interleaved layers also preserve a recent-token sliding-window path. Source: https://arxiv.org/html/2606.19348v1.

## API Migration and Operational Takeaways

If you are using DeepSeek's hosted API or integrating it into tools like Claude Code, there are immediate operational requirements.

### 1. The July 24 API Deadline

The April announcement scheduled `deepseek-chat` and `deepseek-reasoner` to become inaccessible after July 24 at 15:59 UTC; it didn't promise a specific 404 response. That deadline has passed. Today's recommended hosted names are `deepseek-flash` and `deepseek-v4-pro`; they aren't immutable checkpoint pins. Source: https://api-docs.deepseek.com/news/news260424/ and https://api-docs.deepseek.com/quick_start/pricing/.

### 2. Rate Limits and Concurrency

Standard quotas are account-level, 500 for Pro and 2500 for Flash, shared by all keys and user_id values. Expanded accounts additionally have per-user_id limits. Excess concurrency returns 429. A request occupies its slot until the response completes. Source: https://api-docs.deepseek.com/quick_start/rate_limit/.

### 3. Latency on Non-Streaming Agent Calls

Remove the original unsupported 30-second timeout claim. The service sends empty lines for non-streaming keep-alive and SSE comments for streaming, so TTFB isn't necessarily full reasoning time. Check actual client timeout and parser behavior. Thinking defaults to high effort; current thinking mode ignores temperature but honors top_p 0.95-1.0. Tool-bearing Chat Completions turns must preserve prior reasoning_content or receive 400. Sources: https://api-docs.deepseek.com/quick_start/rate_limit/ and https://api-docs.deepseek.com/guides/thinking_mode/.

### 4. Self-Hosting Realities

Open weights do not make V4-Pro a laptop model. Serving 1.6T total parameters requires significant infrastructure.

- The dated checkpoint cards include vLLM and SGLang DSpark recipes, including Pro on 4 GB300 devices. Capacity depends on precision, cache length, concurrency and topology; don't reduce it to a universal 8-GPU minimum. Both cards require custom message encoding rather than a built-in Jinja chat template. Sources: https://huggingface.co/deepseek-ai/DeepSeek-V4-Pro-0813 and https://huggingface.co/deepseek-ai/DeepSeek-V4-Flash-0731.
- Evaluate checkpoint-local quality and serving capacity when you have suitable infrastructure. Hosted V4.1 Flash results can't substitute for a self-hosted V4 Flash 0731 evaluation. No API, model-serving or GPU benchmark was executed in this review.

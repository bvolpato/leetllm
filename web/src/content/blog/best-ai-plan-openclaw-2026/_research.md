## What Actually Matters Under Agent Load

A plan must permit the intended interactive or unattended workload. Check five details:

1. **Documented Routes:** Does OpenClaw actually document the provider route?
2. **Quota Counting:** Does the plan meter tokens, prompts, requests, or a subscription allowance?
3. **Reset Windows:** Do limits reset gradually (rolling), weekly, monthly, or not at all?
4. **Use-Case Limits:** Is the tier restricted strictly to personal or interactive use rather than scripts?
5. **Metered Pricing Start:** Where does pay-as-you-go kick in?

Start with one eligible credential. Add a backup only after a measured failure and an approved workload, data policy and budget justify it. No comparative quality benchmark was run.

## Limit Shapes and Routing Guardrails

Classify the failure before retrying. A subscription restricted to interactive use must not be chosen for production traffic. A backup needs its own allowed workload, budget and data policy; failover may rotate same-provider credentials before switching models. https://docs.openclaw.ai/concepts/model-failover

**Guardrail Checklist:**

- **Route by policy, not just model IDs:** Check workload eligibility and actual quality before sending any task to a subscription.
- **Trim before escalating:** Summarize context before passing a task to the metered API.
- **Avoid the "fixed price" trap:** Treat subscription tiers as scoped capacities with specific queues, rolling windows, and allowlists, not as infinite capacity. Opening the premium API lane for every routine file read is a fast way to burn out a budget.

## Purchase evidence

- Compare regular listed fees on the same billing period, excluding temporary benefits.
- Measure requests, token categories, quota, queue time, all retries, reviewer time and accepted outcomes on representative tasks.
- State whether a subscription cost is incremental spend or an allocated monthly share.
- Add a backup only when a named observed failure justifies its separate budget and permissions.

The routing policy matters as much as the plan. A well-priced agent with poor retry logic will waste quota; a powerful model with no routing discipline will waste money.

## 1. What Ollama Ships

The official Ollama catalog for Qwen3.5 lists seven primary local aliases: `0.8b`, `2b`, `4b`, `9b`, `27b`, `35b`, and `122b`. [Qwen3.5 Library Page](https://ollama.com/library/qwen3.5).

- **Tiny tags (`0.8b` to `4b`):** Candidate configurations for low-memory smoke tests; task quality still needs evaluation.
- **Mainstream Local (`9b`):** The primary tag for existing laptop and coding experiments. It is marked as `latest`, meaning it is a mutable alias rather than a pinned artifact.
- **Larger tags (`27b`, `35b`, `122b`):** Artifact size is a filter, not a fixed hardware category or evidence of usable latency. [Exact Ollama tag catalog](https://ollama.com/library/qwen3.5/tags).

### Dense vs. MoE Tags

The `35b` and `122b` tags are Mixture of Experts (MoE) models, not standard dense models. Qwen3.5 35B-A3B activates 3B parameters per token, while 122B-A10B activates 10B. Active count influences compute but doesn't predict latency or remove full-weight storage. [35B-A3B card](https://huggingface.co/Qwen/Qwen3.5-35B-A3B), [122B-A10B card](https://huggingface.co/Qwen/Qwen3.5-122B-A10B).

## 2. Hardware Sizing and Memory Placement

Before you pick a tag, understand what happens when you send a prompt. Ollama manages model tags and routes requests. Backend choice depends on artifact and platform; the catalog includes MLX tags for Apple Silicon. Don't attribute a runtime-and-quantization comparison solely to model weights. [Ollama repository](https://github.com/ollama/ollama), [official MLX preview](https://ollama.com/blog/mlx).

A 6.6 GB artifact doesn't mean you only need 6.6 GB of RAM. Qwen3.5-9B has 24 Gated DeltaNet layers maintaining recurrent state and eight full-attention layers growing a KV cache. Under one sequence, FP16 K/V, four KV heads and head dimension 256, full-attention KV requires 32,768 bytes per token: 0.25 GiB at 8192 tokens, 2 GiB at 65536. Weights, recurrent state, workspace, image buffers, allocator overhead and other processes are excluded. [9B card](https://huggingface.co/Qwen/Qwen3.5-9B), [exact model configuration](https://huggingface.co/Qwen/Qwen3.5-9B/blob/main/config.json).

### Conservative Sizing Advice

Use published artifact size as a starting filter, then leave headroom. The original fixed 8/12/16/32 GB recommendations weren't measurements and have been removed. Context, concurrency, backend, precision, host versus discrete GPU memory and available reserve change the result.

- Primary rounded alias artifacts are 1.0, 2.7, 3.4, 6.6, 17, 24 and 81 GB in ascending model order. The two smallest use Q8_0; the rest use Q4_K_M. These decimal-GB downloads aren't resident memory. [Tag catalog](https://ollama.com/library/qwen3.5/tags).

> **Sizing Rule:** Disk size is only the first filter. Keep headroom for KV cache, prompt tokens, image tokens, and the operating system.

## 3. Context Length Management

The Qwen3.5 model page advertises 256K native context (262144 tokens); its upstream card describes a separate YaRN extension to 1010000. An ordinary local Ollama invocation doesn't automatically enable that extension. The dedicated Ollama context page documents these VRAM-based defaults, while the FAQ still says 4096. Set context explicitly and inspect `ollama ps`. [9B card](https://huggingface.co/Qwen/Qwen3.5-9B), [context docs](https://docs.ollama.com/context-length), [FAQ](https://docs.ollama.com/faq).

- **Under 24 GiB VRAM:** Defaults to 4K context.
- **24 to 48 GiB VRAM:** Defaults to 32K context.
- **48 GiB or more:** Defaults to 256K context.

"This model supports 256K" isn't the same as "my laptop starts every session at 256K." Ollama recommends at least 64000 tokens for long-context tools; this isn't a hardware-fit guarantee. Use 8192 or lower for the small direct-response smoke test, then measure longer workload needs.

### How to Override Context Length

You can manage context length across different control surfaces:

1. **Via Modelfile (Recommended):** Bake the `num_ctx` into a derived local tag.

```dockerfile
FROM qwen3.5:9b-q4_K_M
PARAMETER num_ctx 8192
PARAMETER temperature 0.3
SYSTEM """You are a precise coding assistant."""
```
2. **Via Server Default:** Start the server with `OLLAMA_CONTEXT_LENGTH=64000 ollama serve`.
3. **Via Request API:** Send `"options": {"num_ctx": 32768}` in native API calls.

## 4. API Compatibility and Workflow

For custom scripts, Ollama publishes compatibility for a subset of OpenAI endpoints, including `/v1/chat/completions` and stateless `/v1/responses`. Prior-response IDs and conversation IDs don't preserve server-side state. [Official Ollama compatibility docs](https://docs.ollama.com/api/openai-compatibility).

Point client code to `http://localhost:11434/v1/`, use a placeholder key (like `ollama`), and set the model to your fully qualified quantization tag (e.g., `qwen3.5:9b-q4_K_M`). Save `/api/show` configuration beside the `/api/tags` digest. The generation contract recommends discovering thinking controls through `/api/show`. [Generate contract](https://docs.ollama.com/api/generate), [current response types](https://github.com/ollama/ollama/blob/main/api/types.go).

**Important Caveat:** If you use `/v1/chat/completions`, Ollama ignores context size set in the request body. You must use a derived Modelfile or set a server-wide `OLLAMA_CONTEXT_LENGTH` to override the VRAM-based default.

## 5. Diagnosing Issues

When performance degrades, run `ollama ps` to verify memory placement. Its CPU/GPU percentages describe placement, not measured utilization. Inspect cold-load time, prompt evaluation, decode and context before attributing a slowdown to one layer. Usage metrics are nanoseconds; prompt_eval_count includes cached input, while prompt_eval_duration describes uncached evaluation. Don't invent missing cache metrics. [Usage contract](https://docs.ollama.com/api/usage).

### Common Failure Fixes

- **Model is unusably slow:** Check `ollama ps`. If CPU offload is high, step down to a smaller tag or reduce the context length.
- **Machine destabilizes during long chats:** Reduce `num_ctx`. Then test `OLLAMA_FLASH_ATTENTION=1` and KV cache quantization (`OLLAMA_KV_CACHE_TYPE`).
- **Inconsistent benchmark results:** Stop using the `latest` or `9b` aliases. Pull a fully qualified quantization tag (e.g., `qwen3.5:9b-q4_K_M`) and record the local manifest digest.
- **OpenAI `/v1` client cannot set context:** Use a Modelfile with `PARAMETER num_ctx` instead.

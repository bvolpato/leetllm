# Manual evidence notes, September 22, 2026

Read the original article, metadata, examples, ten quiz questions, four illustration sources, and banner manually. These notes replace generated research that supplied unsupported model scores/prices, adoption claims, timing ranges, and a mandatory architecture. No automated authoring or delegated review was used.

- [ElementTree](https://docs.python.org/3/library/xml.etree.elementtree.html) documents namespace-expanded tags, direct-child search, and deprecated element truth-value testing. The original parser didn't implement its own namespace or repeated-case contract. The revised fixture defines namespace/status precedence, rejects missing identifiers, and checks repeated cases. It isn't a parser for every report dialect.
- [Python XML security](https://docs.python.org/3/library/xml.html#xml-security) describes Expat-version-dependent protections. Input caps don't replace parser updates, decompression limits, and CPU/memory controls.
- [Docker security](https://docs.docker.com/engine/security/) distinguishes daemon authority, rootless mode, shared kernels, namespaces, and capabilities. A rootful unrestricted daemon is a privileged control plane; a read-only root doesn't forbid interpreting malicious code from writable scratch space.
- [Docker none networking](https://docs.docker.com/engine/network/drivers/none/) retains an isolated loopback network stack. [tmpfs](https://docs.docker.com/engine/storage/tmpfs/) documents memory accounting, mount size/options, and swap caveats. Neither offline networking nor output truncation guarantees confidentiality.
- [Docker resource limits](https://docs.docker.com/engine/containers/resource_constraints/) separate periodic CPU bandwidth from timeouts and describe equal memory/swap limits. [Launch options](https://docs.docker.com/engine/containers/run/) require a real image and compatible profile; the article's illustrative command wasn't executed.
- [Linux cgroup v2](https://cdn.kernel.org/doc/html/latest/admin-guide/cgroup-v2.html) specifies task-creation rejection at PID limits, memory reclaim/OOM behavior, and cgroup.kill. It doesn't say all excessive allocations immediately kill a job or that PID caps terminate running tasks.
- [PID namespaces](https://man7.org/linux/man-pages/man7/pid_namespaces.7.html), [subreapers](https://man7.org/linux/man-pages/man2/PR_SET_CHILD_SUBREAPER.2const.html), and [setsid](https://man7.org/linux/man-pages/man2/setsid.2.html) distinguish namespace-init termination, orphan adoption/waiting, and process-group changes. killpg plus a subreaper isn't complete adversarial descendant containment.
- [gVisor security](https://gvisor.dev/docs/architecture_guide/security/) explains Sentry, Gofer, limited host interactions, and configuration-dependent filesystem paths. [Platforms](https://gvisor.dev/docs/architecture_guide/platforms/) documents systrap replacing ptrace as default in 2023 and ptrace no longer being supported. Removed a stale KVM/ptrace-only diagram, off-host Gofer claim, and unmeasured overhead tiers.
- [Firecracker specification](https://github.com/firecracker-microvm/firecracker/blob/main/SPECIFICATION.md) scopes the 125 ms target to InstanceStart-to-init under a tuned setup, rather than agent readiness. [The original NSDI paper](https://www.usenix.org/conference/nsdi20/presentation/agache) supplies architectural context. Four runtime families aren't an ordered security leaderboard.
- [Modal networking](https://modal.com/docs/guide/sandbox-networking) documents public outbound access by default, full blocking, CIDR controls, and domain allowlists in Beta. The stated TLS/domain-fronting limitations matter. Removed universal managed-platform startup and synchronization claims; E2B documentation couldn't be retrieved reliably in this pass.
- [Wasmtime Python API](https://bytecodealliance.github.io/wasmtime-py/) specifies Store limits and fuel before instantiation. [Release 49](https://github.com/bytecodealliance/wasmtime/releases/tag/v49.0.0) and [PyPI metadata](https://pypi.org/pypi/wasmtime/49.0.0/json) confirm September 21, 2026 publication and Python >=3.9. The revised lab pins 49.0.0; pinning isn't a perpetual security-update policy.
- [Wasmtime interruption](https://docs.wasmtime.dev/examples-interrupting-wasm.html) bounds guest execution with configured fuel or epochs. [Deterministic execution](https://docs.wasmtime.dev/examples-deterministic-wasm-execution.html) separately handles NaNs, relaxed SIMD, growth, and imports. [Security](https://docs.wasmtime.dev/security.html) describes checked guest access and defense in depth; no implementation-immunity claim is made. Guest linear memory isn't host RSS, and fuel isn't a compilation or host-import deadline.
- [HumanEval Section 2.1 and Appendix A](https://arxiv.org/html/2107.03374v2) distinguish an unbiased estimator under sampling assumptions from the fixed-pool combinatorial calculation. Identical code can occur in different sampled indices; repair steps within a trajectory aren't IID samples.
- [SWE-bench evaluation](https://www.swebench.com/SWE-bench/guides/evaluation/) grades patches by repository tests, reports infrastructure failures separately, and doesn't impose a universal agent budget or mandatory multi-turn architecture.

Artifact binding is taught through a synthetic manifest/hash comparison. The receipt is assumed protected by the trusted supervisor; the fixture implements neither signatures nor a production artifact store. Hashing detects changed recorded bytes only when an acceptance step compares them. Private test inputs necessarily reach the worker when used; feedback can disclose hidden-test information.

The executable labs exercise hand-written XML fixtures, hashes, a narrow import-free Wasm interface, and pass@k arithmetic. They don't run arbitrary model-generated Python, Docker/gVisor/Firecracker, hosted sandboxes, resource attacks, or a coding benchmark. Visual inspection and structural checks are separate from claims of complete containment or correctness.

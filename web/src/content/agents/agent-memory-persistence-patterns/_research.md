# Agent memory: manual source notes

Checked September 22, 2026. These notes support this article's individual review; they aren't a generated outline or a completed audit of the corpus.

- [CoALA, section 4.1](https://arxiv.org/html/2309.02427v3): Working memory is runtime state across decision cycles, with a subset synthesized into each prompt. Episodic, semantic, and procedural describe information and functions, not fixed database engines or latency tiers. Procedural memory includes model weights and explicit code; governed skill learning is possible.
- [FlashAttention, appendix C](https://arxiv.org/html/2205.14135): Exact dense attention retains quadratic FLOPs while tiling avoids materializing the full attention matrix in GPU high-bandwidth memory. Separate prompt computation, cached per-token decoding, and KV storage growth.
- [Generative Agents, section 4.1](https://arxiv.org/html/2304.03442v2): Recency uses time since last retrieval in simulation hours and a 0.995 decay factor. Relevance, recency, and importance are min-max normalized and equally weighted in that implementation. This article's event-age, seven-day half-life, and 0.5/0.3/0.2 weights are a synthetic alternative. Exponential ranking decay isn't a universal human forgetting law; raw log-frequency remains unbounded.
- [MemGPT, sections 2.1–2.3](https://arxiv.org/html/2310.08560v2): Main context contains static instructions, writable working context, and a FIFO whose first slot summarizes evicted messages. Messages enter recall storage as they arrive. The paper gives 70% warning and 100% flush as examples, not 85% or universal production defaults. Pagination and host budgeting don't guarantee accurate or unlimited recall. Static instructions aren't a hardware security boundary.
- [Letta V1 memory blocks](https://docs.letta.com/v1-sdk/memory/memory-blocks): The legacy SDK documents labels, descriptions, values, and character limits. Don't present its contracts as the current Agent SDK API.
- [Letta Agent SDK memory](https://docs.letta.com/agent-sdk/memory): Current docs describe a git-backed memory repository projected by MemFS. Files under `system/` enter each prompt; other files are read on demand. Memory edits must be committed and pushed to become retained state. Historical MemGPT function signatures aren't this SDK's contract.
- [LangGraph memory overview](https://docs.langchain.com/oss/python/concepts/memory) and [checkpointers](https://docs.langchain.com/oss/python/langgraph/checkpointers): Thread-scoped state and long-term namespaced records have different jobs. Checkpoints are saved at super-step boundaries, with per-task pending writes supporting recovery. Namespaces aren't authentication or authorization.
- [LangGraph interrupts](https://docs.langchain.com/oss/python/langgraph/interrupts) and [Temporal workflow execution](https://docs.temporal.io/workflow-execution): Recovery depends on recorded execution boundaries and configured durability. An interrupted node can restart; external effects need their own retry and reconciliation contract. A recalled approval note can't establish current permission or whether an effect committed.
- [Claude memory tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/memory-tool): Client-side `view`, `create`, `str_replace`, `insert`, `delete`, and `rename` requests are implemented by the application. The host maps `/memories` to scoped storage and handles size, sensitive data, expiry, and traversal checks. A writable directory doesn't supply those controls automatically.
- [Mem0 paper](https://arxiv.org/html/2504.19413v1): Model-assisted extraction and updates produce candidate records and retrieval context. Conversational benchmark findings don't establish coding-agent accuracy or a universal latency SLA. Avoid the former note's unsupported claim that one database is the industry standard.
- [PostgreSQL row security](https://www.postgresql.org/docs/current/ddl-rowsecurity.html): RLS applies inside the database, with superuser, BYPASSRLS, and usual table-owner exceptions. Trusted request scope and pooled connection handling matter. A prompt instruction or optional search filter isn't a storage access boundary.
- [OWASP LLM01](https://genai.owasp.org/llmrisk/llm01-prompt-injection/): Delimiters, classifiers, keyword rules, and record labels don't reliably turn hostile text into trusted data. Admission, least privilege, and action checks must remain separate. Hashes don't prove truth or authorship; asynchronous tombstones don't instantly erase caches, assembled prompts, logs, or backups.
- [OpenAI Assistants migration](https://developers.openai.com/api/docs/assistants/migration): The former research packet recommended a sunset API as a current integration. OpenAI's documented August 26, 2026 shutdown has passed. Remove that recommendation; managed conversation history also isn't learned model weights or permission to perform effects.

The local labs test bounded data movement, ranking, scoped lookups, preference resolution, admission predicates, SQLite source/version/access joins, and extraction failure modes. They don't test model recall quality, hosted services, database RLS, distributed revocation, power-loss durability, or a complete effect executor. Keep those limits visible beside the examples.

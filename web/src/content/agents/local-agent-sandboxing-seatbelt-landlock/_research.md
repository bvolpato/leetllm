# Evidence reviewed October 31, 2026

The article, six-question quiz, original two Mermaid diagrams, code fragments and complete path-policy example were read individually. The native figures use supplied policy sketches and deterministic local fixtures. No malicious hook, real credential, remote request, Landlock policy or macOS sandbox was executed.

- [Landlock userspace API](https://docs.kernel.org/userspace-api/landlock.html) describes handled rights, additive grants within each layer, runtime ABI probing and calling-thread enforcement. Existing-thread synchronization arrived in ABI 8. ABI 11 can set `no_new_privs` on successful enforcement; the article's manual path sets it first. The displayed ABI 1–6 list is explicitly a subset. The C fragment assumes ABI 3 or newer and omits grant insertion and enforcement. Restricting a selected child with an allow rule cannot subtract rights already granted by a writable parent in that layer.
- [Seccomp filter documentation](https://docs.kernel.org/userspace-api/seccomp_filter.html) describes syscall/argument filtering as one component of containment. It does not inspect pointed-to strings or replace filesystem policy. The shown Bubblewrap command has no seccomp-filter descriptor. The [Bubblewrap manual](https://github.com/containers/bubblewrap/blob/main/bwrap.xml) documents loading compiled filters through `--seccomp` and related options. Its namespace/mount sketch is unexecuted here. Read-only Git metadata and process-parent lifetime controls leave other writable host-consumed inputs and cleanup work to review.
- [Apple App Sandbox](https://developer.apple.com/documentation/security/app-sandbox) describes resources granted through entitlements. [Chromium's macOS Seatbelt implementation](https://chromium.googlesource.com/chromium/src/+/main/sandbox/mac/seatbelt.cc) implements parameterized profile setup. It is implementation evidence rather than a stable Apple public API contract. The C and Scheme fragments are incomplete integration examples. All four parameters used by the profile now have supplied paths. The broad project write grant still covers `.git`, which the figure highlights as a policy issue rather than a platform limitation.
- [Git hooks](https://git-scm.com/docs/githooks) documents executable hooks in the configured hooks directory and the post-checkout trigger after checkout/switch updates the worktree. The comparison assumes trusted initial Git metadata. Blocking an untrusted planting write preserves that initial state; it does not inspect an existing hook. Configured filesystem monitors and external diffs have operation-specific triggers. IDE and directory-tool execution also depends on the feature and its trust/approval settings.

The broker figure supplies one fixed path, a host-owned upstream origin, four request cases and an adversarial reply with an extra fake field. The local verification admits GET for the approved route, rejects POST/DELETE and another repository before simulated dispatch, then selects `number` and `state`. It demonstrates that declared fixture contract only. Production brokers need authenticated capability provenance, URL/path normalization, redirect and egress controls, credential handling and a reviewed output policy.

The original Python program imports `ctypes` and declares constants but calls no Landlock API. Its `PathValidator` is a resolve-and-compare exercise. All five original decisions are asserted, while stdout omits `.git/config`. The exact protected targets are `.git/hooks`, `.git/config`, `.vscode` and `.env`; `.git` itself and the neighboring `.env.local` path pass that helper. The tree makes those boundaries explicit without claiming secure file-opening mediation. The sibling `.ssh` path in the temporary fixture is outside the fixture root, rather than a read of the developer's real home directory.

The reference keys distinguish Landlock's userspace API, Apple's entitlement-based App Sandbox documentation, and Chromium's custom-profile implementation. Each source supports its own mechanism and scope.

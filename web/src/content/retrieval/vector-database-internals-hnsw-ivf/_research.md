# Vector database internals: manual source review

Checked September 22, 2026. Body, metadata, ten quiz questions, five native illustration definitions, banner source/provenance, and Mermaid definition reviewed individually. These notes replace the generated outline's unsupported speed/recall table and its incorrect PQ citation and units.

## Flat search and what dimension does not establish

- Exact scoring processes `N*d` components; raw float32 storage uses `N*d*4` bytes. Neither expression establishes wall time or QPS. Exact ANN recall requires matching vectors, metric, filters, numerical conventions, and ties. Faiss's scoring contract: https://github.com/facebookresearch/faiss/wiki/MetricType-and-distances
- SciPy warns against expecting k-d trees to outperform brute force in high dimensions, including dimension 20. It does not prove universal failure above that dimension. Padding 1D points with zeros preserves their unequal distances in 768D. Similar radii also do not imply similar ball volumes: https://docs.scipy.org/doc/scipy/reference/generated/scipy.spatial.KDTree.html

## HNSW: exploration, not an unseen-neighbor certificate

- Read the paper's layer distribution, insertion/search algorithms, diversity selection, and parameter discussion; visually inspected PDF pages 4 and 5. Algorithm 2 bounds the retained set, not the expansion queue, visited set, or number of scores. The stopping condition does not prove all unseen points are farther. Algorithm 4 can extend candidates and refill rejected connections. The heuristic's distance test does not guarantee an actual selected-neighbor-to-rejected-node edge. Reciprocal insertion followed by pruning can leave asymmetric links: https://arxiv.org/pdf/1603.09320
- `mL=1/ln(M)` requires `M>1`; fixed-level population estimates do not guarantee a unique highest-layer node. Base-layer `2M` is a common cap, not a connectivity guarantee. The paper's complexity analysis uses graph assumptions; removed a universal logarithmic claim: https://arxiv.org/pdf/1603.09320
- Hnswlib requires query `ef >= k`. The toy builder intentionally uses nearest-only selection and a single next-layer entry. Its search-only bridge counterexample shows why a wider retained set can reach an otherwise missed nearest node: https://github.com/nmslib/hnswlib/blob/master/ALGO_PARAMS.md

## IVF, PQ, and comparable scores

- Faiss lists coarse quantizers, HNSW encodings, and storage formulas. IVF-Flat becomes exhaustive when every list is scanned without other limits; IVF-PQ still loses information. Added lists improve candidate coverage but compressed-score errors can lower final recall against originals. The list ID is an argmin integer, not the centroid vector. Top-centroid selection does not require a full sort: https://github.com/facebookresearch/faiss/wiki/Faiss-indexes
- Separate sub-quantizers do not assert statistical independence of input chunks. A 768D float32 vector is 3,072 **bytes**, not bits; a 96-byte code gives 32x code-only compression. Original PQ metadata retains the canonical DOI; the publisher and author-hosted full-text copies were inaccessible. Mechanisms were checked against official Faiss documentation and the OPQ paper's PQ description rather than claiming a complete reread of the original: https://doi.org/10.1109/TPAMI.2010.57
- Ordinary ADC uses byte code indices into floating-point squared-distance tables. The 96-by-256 float32 table is exactly 96 KiB, not 96 KB; no guaranteed L2 residency or latency follows. Residual IVF-PQ normally uses query residual/list terms and may allocate larger precomputed tables. Translating both vectors and a codebook leaves reconstruction error unchanged: https://github.com/facebookresearch/faiss/wiki/Implementation-notes
- OPQ jointly optimizes decomposition and codebooks for quantization distortion; variance balancing alone is not its general objective. Read the abstract and introduction's objective and comparison. This is Ge et al.'s 2013 paper, not Jégou et al.'s original PQ paper: https://www.cv-foundation.org/openaccess/content_cvpr_2013/papers/Ge_Optimized_Product_Quantization_2013_CVPR_paper.pdf
- Faiss factory strings permit a changed OPQ output dimension. `OPQ96_384` gives four dimensions per chunk and is not a square distance-preserving rotation of the 768D input: https://github.com/facebookresearch/faiss/wiki/The-index-factory
- The authored same-code fixture distinguishes reconstructed-vector scores from original-vector distances. Reranking an already truncated buffer cannot recover a missing original; overfetching helps only if the missing candidate enters the buffer. Distributed merges of PQ estimates retain score errors. Faiss's exact-score conventions: https://github.com/facebookresearch/faiss/wiki/MetricType-and-distances

## Filters and distributed tails

- `L*s` needs each retrieved candidate's marginal match probability to be `s`; `(1-s)^L` additionally needs independent match indicators. Global corpus selectivity need not apply near the query. An all-or-none buffer has the same expectation but a different empty probability. These are authored probability models, not database benchmarks.
- pgvector's iterative scans stop when enough results or scan/resource limits are reached, not on an automatic latency deadline. Checked `hnsw.max_scan_tuples`, scan memory multiplier, `ivfflat.max_probes`, and supported ordering modes: https://github.com/pgvector/pgvector#iterative-index-scans
- Weaviate distinguishes sweeping traversal from its custom ACORN. ACORN skips distance evaluations for nonmatches, uses multi-hop traversal and eligible entry points; the current guide names it the default from v1.34. A generic allow-list traversal is not a full description of that implementation, nor a universal recall guarantee: https://docs.weaviate.io/weaviate/concepts/filtering
- The DiskANN abstract's historical SIFT1B figures remain explicitly scoped to its 16-core/64-GB-plus-SSD setup. No current cross-workload speed guarantee: https://proceedings.neurips.cc/paper/2019/hash/09853c7fb1d3f8ee67a61b6bf4a7f8e6-Abstract.html
- Local exact top-K sets suffice for disjoint complete shards with the same metric, representation, and tie order. ANN misses, missing shards, deduplication, grouping, and reranking can invalidate that proof's prerequisites. Merge input streams number `S`, not `K`.
- `t99` is a time threshold; 0.99 is a probability. Independent shards yield `0.99**S` at that common threshold; perfect correlation yields 0.99. For twenty iid shards, the maximum's p99 corresponds to single-shard percentile 99.9498. The drawn response/merge times are invented examples, not percentiles or measurements. The executable probability exercises verify arithmetic only.

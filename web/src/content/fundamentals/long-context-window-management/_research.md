# Manually checked source notes, September 22, 2026

Relevant selections read for this bundle, not complete upstream projects or every paper. Fourteen marked examples are CPU configuration/arithmetic/control-flow exercises. No model, GPU serving engine, production capacity test, or quality benchmark was run.

- [Llama 3 report, HTML v3](https://arxiv.org/html/2407.21783v3), architecture/Table 3: 70B reference setup has 80 layers, hidden size 8192, 64 query heads, eight KV heads, and RoPE base 500,000. The 40 GiB at 131,072 BF16 tokens is a raw uniform-layer sum, not per-device measured residency or an actual weight-file manifest.
- [Pinned Gemma 4 12B config](https://huggingface.co/google/gemma-4-12B/blob/023679ed352de9bb66cc873c9009ce3482585c08/config.json), full JSON retrieved through its resolve URL: 40 sliding layers with eight 256-wide KV heads/window 1024, eight full layers with one 512-wide KV head, and no cross-layer KV sharing. Per-layer retained lengths and widths matter. Model dtype doesn't establish cache dtype/physical eviction.
- [Pinned Gemma attention/cache source](https://github.com/huggingface/transformers/blob/2c4914fb939fe9de0d8e7a798af4684d552f18b4/src/transformers/models/gemma4_unified/modeling_gemma4_unified.py), constructor and forward selections: shared global projection still receives separate key norm/RoPE and value norm before two states reach cache.update. The assumed two-array BF16 worksheet gives 2.3125 GiB, not the incorrect uniform 48 GiB.
- [Mistral 7B, HTML v1](https://arxiv.org/html/2310.06825v1), section 2/Table 1: 4096 local window, stacked receptive fields, and rolling cache. A one-layer window isn't the whole network's receptive field or a guarantee of exact distant-fact retrieval.
- [Gemma 2 report](https://storage.googleapis.com/deepmind-media/gemma/gemma-2-report.pdf), page 2 architecture/Table 1 text: alternating 4096 local/8192 global spans. Historical illustration, not a current family-wide window specification. No PDF figure inspection is claimed.
- [StreamingLLM, HTML v1](https://arxiv.org/html/2309.17453v1), attention-sink and rolling-cache passages: retained initial states stabilize the tested models, without restoring every evicted fact or establishing one universal sink count.
- [Transformers RoPE main](https://huggingface.co/docs/transformers/main/internal/rope_utils) and [5.17.0 guide](https://huggingface.co/docs/transformers/v5.17.0/internal/rope_utils), variant/configuration/per-layer-type passages: current rope_parameters schema and model-specific settings. The pinned CPU LlamaConfig example doesn't load weights or enlarge max_position_embeddings when setting a factor.
- [YaRN, HTML v2](https://arxiv.org/html/2309.00071v2), sections 2.2 and 3.1–3.4: position interpolation, NTK-aware versus NTK-by-parts, linear frequency ramp, attention-logit scaling, and dynamic-basis cache consistency. Output sampling temperature is separate. The unit-vector exercise demonstrates an intended-basis mismatch, not a tested library defect.
- [LongRoPE, HTML v1](https://arxiv.org/html/2402.13753v1), abstract/introduction/method overview: searched dimension/position nonuniformity, progressive extension and short-context readjustment. Tested long-window results don't establish a generic software switch or reliable arbitrary synthesis.
- [Lost in the Middle](https://aclanthology.org/2024.tacl-1.9/), abstract/task description: observed beginning/end advantage in specified QA/key-value evaluations, not a law for all current models/tasks.
- [Chroma Context Rot](https://www.trychroma.com/research/context-rot), contributions and needle-similarity experiment: 18 evaluated models, input-length/distractor effects, and no notable position variation in the specified NIAH experiment. Length degradation and a middle-position dip aren't interchangeable findings. Top-k manual absence checks don't prove absence from an entire corpus; the lesson doesn't make that inference.
- [GQA, HTML v3](https://arxiv.org/html/2305.13245v3), abstract/architecture selections: head sharing and conversion with uptraining. Editing head-count configuration alone doesn't preserve an arbitrary checkpoint.
- [DeepSeek-V2, HTML v5](https://arxiv.org/html/2405.04434v5), abstract/MLA selections: compressed latent plus positional state; reported 93.3% reduction is versus DeepSeek 67B, not a universal cache ratio or serving flag.
- [vLLM quantized cache](https://docs.vllm.ai/en/latest/features/quantization/quantized_kvcache/), calibration/granularity/skipped-layer/FA3 passages: default unit scales, dataset calibration, layer exclusions, backend constraints, and query quantization in the documented FA3 FP8 path. Native-dtype skipped layers and extra scales qualify the raw 2x payload reduction.
- [vLLM optimization](https://docs.vllm.ai/en/latest/configuration/optimization/), chunked-prefill/scheduler passages: decode-prioritized interleaving and token-budget trade-offs. Smaller chunks can protect ITL while hurting the long request's TTFT; no universal improvement or tuning value is asserted.
- [vLLM prefix cache](https://docs.vllm.ai/en/stable/design/prefix_caching/), hash/full-block/isolation passages: parent-token dependency, LoRA/multimodal identity, optional salts, eviction, and full-block reuse. Reuse avoids new prompt work, not decode attention, request token accounting, or durable transcript storage. Reused preceding manually inspected PagedAttention/FlashAttention selections for allocation and IO scope.
- [Ring Attention, HTML v4](https://arxiv.org/html/2310.01889v4), block exchange/cost and training selections: overlap depends on transfer/computation costs; scaling a research training run doesn't establish a serving engine's support. Kept the original preprint citation rather than infer conference acceptance from a citing paper.
- [vLLM context parallel](https://docs.vllm.ai/en/latest/serving/context_parallel_deployment/) and [source guide](https://github.com/vllm-project/vllm/blob/main/docs/serving/context_parallel_deployment.md), separate prefill/decode passages: supported decode token-history sharding within TP ranks versus actively developed prefill approaches. Backend/group constraints and communication remain.
- [NIAH project](https://github.com/gkamradt/needle-in-a-haystack), built-in tasks/result-reconstruction selections: classic single-fact testing plus current multi/UUID-chain paths and actual-placement metadata. The published toy reader isn't a language model.
- [RULER, HTML v2](https://arxiv.org/html/2404.06654v2), abstract/task overview: synthetic retrieval, variable tracking, aggregation, and QA. Its effective-context threshold is benchmark-specific, not a general quality guarantee.

Reproduced the original float-admission helper's 1.0//0.1 result of nine, boolean acceptance, and huge-integer OverflowError. Integer byte counts remove that floor-division ambiguity. Reproduced the needle helper's boolean depth acceptance and huge-integer OverflowError; type/bounds checks now reject these before conversion. The equal-mean depth comparison illustrates identical averages with different per-depth recall and doesn't certify an actual release.

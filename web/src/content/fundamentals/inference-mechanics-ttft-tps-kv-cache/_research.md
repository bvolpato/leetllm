# Manual source review: inference mechanics

Reviewed September 22, 2026. Original article, ten questions, generated research, three native illustration sources, both Mermaid definitions, banner source/provenance, and all seventeen original reference records read individually.

- NVIDIA's [shipping H100 specification](https://www.nvidia.com/en-us/data-center/h100/) lists 1,979 BF16 TFLOPS for SXM **with sparsity** and 3.35 TB/s HBM bandwidth. The [Hopper architecture explanation](https://developer.nvidia.com/blog/nvidia-hopper-architecture-in-depth/) explains the factor-of-two structured-sparse throughput multiplier. Dense throughput of about 989.5 TFLOPS and a 295.4 FLOPs/byte ridge are derived from rounded shipping values, not the preliminary 2022 performance table. FLOPs/peak does not measure idle cycles.
- Williams, Waterman, and Patterson's [author manuscript](https://www2.eecs.berkeley.edu/Pubs/TechRpts/2008/Archive/EECS-2008-134.pdf), pages 3–4, defines off-chip traffic after cache filtering and the roofline as a bound. A weight-only intensity of N for BF16 linear projections omits activation, attention, and repeated-load traffic. Kernel location below a roof does not identify its cause by itself.
- NVIDIA's [Nsight Compute guide](https://docs.nvidia.com/nsight-compute/ProfilingGuide/) documents metric queries, counter roll-ups, and profiling replay/overhead. Counter availability depends on GPU and tool version. Profiled kernel time and unprofiled service latency are different measurements.
- [Hugging Face's cache explanation](https://huggingface.co/docs/transformers/en/cache_explanation) supports retaining old K/V and computing only new projections. Full-attention queries still read growing history; caching does not remove quadratic total attention work over a growing sequence. P + O − 1 applies to ordinary generation with O ≥ 1 and all logical positions retained, not allocated page capacity.
- [Qwen3.6-27B's model card](https://huggingface.co/Qwen/Qwen3.6-27B) lists 64 layers, sixteen attention layers, forty-eight Gated DeltaNet layers, 24 query heads, four KV heads, attention head dimension 256, hidden size 5,120, and native context 262,144. Thus head dimension is not hidden size divided by query heads. The 4,096-position example is chosen cached length, not its context limit. Standard growing-KV arithmetic omits recurrent state and deployment overhead.
- Current official vLLM documentation source was inspected directly in `docs/design/metrics.md`, `docs/configuration/optimization.md`, and `docs/features/quantization/quantized_kvcache.md`. V1 arrival is recorded in the front end before tokenization. Iteration events may contain multiple tokens; request TPOT and event ITL need different weighting. Mean request TPS is not the inverse of mean request TPOT. V1 chunked scheduling prioritizes decode and uses remaining batched-token capacity for prefill in mixed batches. FP8 cache calibration and backend support require explicit checks; saved payload bytes do not guarantee faster inference.
- [Orca](https://www.usenix.org/conference/osdi22/presentation/yu) supports iteration-level scheduling. [PagedAttention](https://arxiv.org/abs/2309.06180) supports fixed-block mapping and sharing, not a universal less-than-four-percent waste guarantee. Tail waste is less than one block in positions, but can be a high fraction of a short sequence's reservation. [GQA](https://arxiv.org/abs/2305.13245) supports intermediate KV-head counts; raw savings depend on the actual query/KV ratio.
- [Sarathi](https://arxiv.org/abs/2308.16369) combines a prefill chunk and decodes in decode-maximal batches. The article's alternating CPU trace isolates scheduling turns and supplies no timing or vLLM implementation claim.
- [Splitwise](https://arxiv.org/abs/2311.18677), [DistServe](https://arxiv.org/abs/2401.09670), and [Mooncake](https://arxiv.org/abs/2407.00079) support separate phase resources and state-transfer tradeoffs. The old research packet misidentified DistServe as 2401.05440. Disaggregation removes direct phase compute interference between separate pools, not all queueing or shared-network contention. Preferred tensor-parallel degree is workload-specific. Raw K/V transfer excludes hybrid recurrent state; byte/bandwidth is an ideal lower bound, not full handoff latency or a net saving across different requests.
- [FlashAttention](https://arxiv.org/abs/2205.14135) reduces attention HBM accesses. [KVQuant](https://arxiv.org/abs/2401.18079) and [KIVI](https://arxiv.org/abs/2402.02750) explore specialized low-bit caches. Their results are historical model/hardware experiments, not universal quality or speed guarantees for this example.

New CPU exercises expose dense/sparse roof selection, inversion of averages, chunk-event accounting, and paged tail waste. Existing arithmetic and admission examples remain explanatory fixtures. No model, GPU workload, FP8 quality experiment, network handoff, serving benchmark, or deployment was run. Final render and validation evidence is recorded in the repository review ledger.

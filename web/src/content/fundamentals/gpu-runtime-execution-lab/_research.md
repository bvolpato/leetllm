# Manual source notes: GPU runtime execution lab

Reviewed September 22, 2026. Full original 625-line article, metadata, two marked examples, ten questions, eight original reference records, 107-line generated research, both downloadable Python files, both native sources, and banner source/text read directly.

- Model architecture, fusion, shape, backend, and host/device environment change launch counts and timings. Removed fixed kernel/host microsecond claims and an unsupported sample benchmark receipt. The retained amortization example uses declared assumed costs. [Historical graph benchmark](https://developer.nvidia.com/blog/constant-time-launch-for-straight-line-cuda-graphs-and-other-performance-enhancements/).
- Streams specify ordering, not a guaranteed physical driver queue. API asynchronicity doesn't promise an immediate return under every resource condition; copy direction/memory types matter. [API synchronization](https://docs.nvidia.com/cuda/cuda-runtime-api/api-sync-behavior.html).
- Legacy synchronization is scoped to one context's blocking streams. Per-thread default streams aren't non-blocking and synchronize with legacy when both are used. [Stream synchronization](https://docs.nvidia.com/cuda/cuda-runtime-api/stream-sync-behavior.html).
- Unrecorded events represent empty work. Waits observe the most recent recorded state at the time of the wait, not future records. Removed undefined-behavior and universal latency claims. [Events](https://docs.nvidia.com/cuda/cuda-runtime-api/cuda_runtime_api/group__CUDART__EVENT.html), [streams](https://docs.nvidia.com/cuda/cuda-runtime-api/cuda_runtime_api/group__CUDART__STREAM.html).
- Host submission, stream event span, and completed wall time overlap. Event spans include idle gaps between markers. Premature raw CPU reads don't automatically wait; disjoint regions can share an allocation. Pinning applies to appropriate host transfers, not every device buffer. [Asynchronous execution](https://docs.nvidia.com/cuda/cuda-programming-guide/02-basics/asynchronous-execution.html).
- Capture accepts any non-legacy CUDA stream. Ordinary CPU allocations aren't generally banned or replayed. Uncaptured cudaMalloc has mode-dependent restrictions; allocator-aware graph allocations differ. Updating a graph requires topology, matching/order, and node restrictions; supported conditional/enable APIs allow some execution variation. [Graphs](https://docs.nvidia.com/cuda/cuda-programming-guide/04-special-topics/cuda-graphs.html).
- Captured virtual pointers persist after Python rebinding; retain allocations and order in-place updates/results. PyTorch 2.14 default keep_graph=False instantiates at capture end, whereas keep_graph=True changes that contract. [CUDA semantics](https://docs.pytorch.org/docs/2.14/notes/cuda.html), [CUDAGraph API](https://docs.pytorch.org/docs/2.14/generated/torch.cuda.CUDAGraph.html).
- Current vLLM graph dispatch uses runtime mode and multiple batch properties. SGLang separates prefill/decode graph configuration. Padding must protect reductions and side effects; a new CPU example exposes dummy zeros contributing two extra units after affine/square. [vLLM design](https://docs.vllm.ai/en/latest/design/cuda_graphs/), [SGLang arguments](https://docs.sglang.io/docs/advanced_features/server_arguments).
- Persistent kernels need neither process-long lifetime nor cooperative launch unless they require grid-wide group synchronization. Direct CPU/GPU queues require a supported memory/atomic contract and compatible system-scope ordering; device-scope atomicAdd plus a fence alone doesn't specify one. Removed invented nanosecond dispatch, watchdog immunity, fairness, and automatic stream-reset claims. [Cooperative Groups](https://docs.nvidia.com/cuda/cuda-programming-guide/04-special-topics/cooperative-groups.html), [atomic scopes](https://docs.nvidia.com/cuda/cuda-programming-guide/05-appendices/cpp-language-extensions.html).
- Receipt schema 3 records each mode's buffer contract and names PyTorch's CUDA build accurately. The script measures a reused D2D/affine/square/reduction chain with averages and selected correctness checks. It excludes context/allocation/first-replay costs; it doesn't benchmark host transfers, request latency tails, or prove cache residency. Source review and CPU helper checks don't establish GPU performance.

# Manual source notes: GEMM from scalar CUDA to WMMA

Reviewed September 22, 2026. Full article, downloaded CUDA/Python sources, illustrations, quiz, and original bibliography read directly. These notes support this bundle; they aren't an article-generation template.

- Source operand loads, warp address sectors, shared-memory service groups, and HBM traffic have different denominators. The aligned first-warp example counts 33 versus 9 sectors across two loads and the final store, not every loop iteration. Caches can change physical traffic. [CUDA Best Practices](https://docs.nvidia.com/cuda/cuda-c-best-practices-guide/index.html).
- The shown 16-by-16 shared kernel's inner A/B reads are broadcast patterns without scalar bank conflicts. A genuine column access at word 32*lane+k has 32 distinct words in one bank. Padding or a matching producer/consumer permutation can alter that pattern. Scalar XOR doesn't automatically preserve logical float4 order. [CUDA Best Practices](https://docs.nvidia.com/cuda/cuda-c-best-practices-guide/index.html).
- __syncthreads waits for non-exited threads. Early exit isn't by itself proof of a hang; in this cooperative kernel it can omit input values needed by other threads. Conditional barriers still require uniform participation by the relevant threads. [CUDA language extensions](https://docs.nvidia.com/cuda/cuda-programming-guide/05-appendices/cpp-language-extensions.html).
- WMMA requires warp-wide matching calls, aligned pointers, legal strides, and valid full-fragment memory. Global padding is the lab's choice; guarded copies into aligned shared tail tiles are another implementation strategy. FP16 input storage doesn't require FP16 product rounding or mandatory FP32 accumulation. [WMMA API](https://docs.nvidia.com/cuda/cuda-programming-guide/05-appendices/cpp-language-extensions.html), [original Volta explanation](https://developer.nvidia.com/blog/programming-tensor-cores-cuda-9/), [PTX arithmetic rules](https://docs.nvidia.com/cuda/parallel-thread-execution/index.html).
- Rounding absorption around 1024 isn't underflow. FP16 negative and positive updates can have different neighboring spacing across a binade boundary. The CPU struct exercise checks representation rounding, not Tensor Core internal execution. [Python struct](https://docs.python.org/3/library/struct.html).
- Compare WMMA against a high-precision reference for rounded inputs to check its arithmetic, then against the original-input reference to expose quantization plus arithmetic error. The latter statistic isn't a downstream model-quality guarantee. The downloaded lab has one poisoned precheck, five warmups, and repeated event timing; its reused buffers don't prove cache residency.
- A100 80GB SXM's named ceilings are 2,039 GB/s, 19.5 FP32 TFLOPS, and 312 dense FP16 Tensor Core TFLOPS. The 624 FP16 figure needs sparsity. An HBM knee must be compared with HBM intensity, not an unmeasured panel-load ratio. [NVIDIA specifications](https://www.nvidia.com/en-us/data-center/a100/).
- The shared/register/WMMA panel-load models are 4, 6.4, and 8 FLOP/B. WMMA's inputs are half-size; including its FP32 output store gives 8K/(K+16). Shape 73-by-61 with K=67 has 596,702 useful FLOPs versus 819,200 after this lab's padding, 37.3% extra nominal work.
- More pipeline stages hide latency without inherently increasing tile reuse. Low occupancy can coexist with productive pipelining. CTA scheduling may improve last-level-cache reuse. [CUTLASS Efficient GEMM](https://docs.nvidia.com/cutlass/latest/media/docs/cpp/efficient_gemm.html).
- Hopper WGMMA uses 128 threads, B in shared memory, A in shared memory or registers, and register accumulators. Blackwell tcgen05 introduces Tensor Memory. These aren't the same operand/accumulator path as the introductory WMMA kernel. [PTX](https://docs.nvidia.com/cuda/parallel-thread-execution/index.html).
- CUDA 13.x no longer supplies offline compilation for Volta; a compatible older toolkit is needed for that legacy target. No CUDA compilation, GPU execution, sanitizer run, hardware timing, or profiling was available for this review. [CUDA 13.0 release notes](https://docs.nvidia.com/cuda/archive/13.0.0/cuda-toolkit-release-notes/index.html).

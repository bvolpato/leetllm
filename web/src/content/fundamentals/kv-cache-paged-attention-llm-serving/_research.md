# KV Cache & PagedAttention: manual source notes

Checked September 22, 2026. Relevant mechanisms and passages were read directly; this is not an automatic review report or a review of entire upstream repositories.

- [PagedAttention paper](https://arxiv.org/html/2309.06180): section 5 uses A100 deployments, specific OPT/Llama models, synthesized ShareGPT/Alpaca lengths, and Poisson arrivals. The 2–4× headline concerns throughput, not a guaranteed concurrency increase. Orca baselines were reimplemented under differing reservation assumptions. The kernel microbenchmark reports 20–26% higher latency than FasterTransformer's kernel. Block-size results differ by dataset. The paper explicitly allows separate physical storage for heads and layers.
- [Authors' introduction](https://vllm.ai/blog/2023-06-20-vllm): the historical 60–80% waste and under-4% tail figures describe the evaluated settings. Reference counts and copy-on-write permit sharing; safe concurrent reads still consume hardware resources. A full shared prefix can be followed by a new private block without copying its old contents.
- [Historical kernel walkthrough](https://docs.vllm.ai/en/latest/design/paged_attention/): the page warns that it no longer represents current code. Its warps process KV blocks, and its implementation stores intermediate logits in shared memory. Do not describe every paged kernel as one warp per head, register-only addressing, a specified 128-bit load instruction, or FlashAttention online softmax.
- [NVIDIA stream-ordered allocator](https://developer.nvidia.com/blog/using-cuda-stream-ordered-memory-allocator-part-1/): pool-backed asynchronous allocation is an alternative to globally synchronizing operations. Every access must precede deallocation in the appropriate stream ordering. Static maximum-length reservation isn't inevitable.
- [vAttention](https://arxiv.org/abs/2405.04437): dynamic physical backing preserves contiguous virtual addresses for existing attention kernels. Dynamic batching doesn't require one particular cache layout.
- [vLLM prefix design](https://docs.vllm.ai/en/stable/design/prefix_caching/) and its current official Markdown source: full-block cache keys, reuse boundaries, reference counts, eviction, and V1 append-only tables. Duplicate full blocks can remain until a request is freed. An unreferenced cached block is available to the free queue until it is reused/evicted; freeing ownership doesn't necessarily erase retained prefix contents.
- [v0.28.0 cache manager](https://github.com/vllm-project/vllm/blob/v0.28.0/vllm/v1/core/kv_cache_manager.py), get_computed_blocks, and current main: the hit limit is request.num_tokens - 1 to obtain logits. Block alignment can force a whole last block to be recomputed. The lesson's full-attention warm-cache calculation models that boundary, not hybrid-group matching or future versions.
- [Current optimization guide source](https://github.com/vllm-project/vllm/blob/main/docs/configuration/optimization.md): V1 defaults to recompute preemption. Chunked prefill can mix with decodes under a token budget. Neither chunking nor packing guarantees an inter-token deadline. [Offload guide source](https://github.com/vllm-project/vllm/blob/main/docs/features/kv_offloading_usage.md): optional connectors promote completed cache blocks through GPU/CPU tiers; this differs from the legacy scheduler's swap mode.
- [GPT-3 table 2.1 and architecture section](https://arxiv.org/html/2005.14165): 175B has 96 layers, 96 heads, and head width 128; original context is 2,048. The model alternates dense and locally banded sparse attention. Lesson arithmetic explicitly extrapolates full retention beyond that context. Original Llama 3 shapes/context were checked against the model card during the preceding attention review.
- [Orca abstract](https://www.usenix.org/conference/osdi22/presentation/yu): the historical system combines iteration-level scheduling with selective batching. Its 36.9× comparison does not isolate one mechanism.
- [SGLang section 3](https://arxiv.org/html/2312.07104): radix edges store token sequences; unused LRU leaves are evictable, while running requests hold references. The lesson describes the original policy rather than every modern backend.
- [SnapKV abstract](https://arxiv.org/abs/2404.14469): selects clustered important positions per head using an observation window at the end of the prompt, before generation. Corrected the reference's author initial and its claim that observation happens in early generation. [H2O abstract](https://arxiv.org/abs/2306.14048): retains recent and heavy-hitter tokens. Both are approximate retention schemes requiring task evaluation.
- [KIVI sections 3.3 and 4](https://arxiv.org/html/2402.02750): per-channel keys, per-token values, and recent full-precision residual state. [CacheGen reconstruction](https://arxiv.org/html/2310.07240): independently decoded chunks reconstruct the KV tensor; transport/storage compression doesn't itself guarantee smaller reconstructed local tensors. Relevant FlashInfer, GQA/MQA, MLA, Mooncake, and DistServe passages were also checked in this or the immediately preceding individual reviews.

The examples are authored CPU fixtures. They establish payload arithmetic, valid logical reads, failure-state preservation, and a scoped cache-hit boundary. They are not pretrained-model runs, GPU traffic measurements, tenant-isolation experiments, or serving benchmarks. Occupied cache slots differ from the resident size of a preallocated GPU pool. Tail-waste percentages exclude extra reservations, hybrid groups, duplicates, and non-KV overhead.

# Quantization source notes, manually reviewed September 22, 2026

- Read the complete article, metadata, seven original CPU examples, ten questions, twelve original reference records, all six illustration sources, and banner source/text. Replaced the generated packet's invented acronym expansions, universal bandwidth/quality claims, and unsupported environment rankings.
- The [Qwen3.6-27B card](https://huggingface.co/Qwen/Qwen3.6-27B) describes a 27B language component with a vision encoder and 64 hybrid recurrent/attention blocks. The lesson's 27-billion-weight arithmetic is a hypothetical uniform-payload budget, not an inspected quantized Qwen tensor inventory or context-fit measurement.
- The general affine zero-point includes q_min. Include zero in the calibrated interval, handle all-zero input separately, and account for rounding/clipping. SiLU can be negative. Group scales on the reduction axis can't all be factored outside the contraction.
- Executed the original codec before editing: minimum-positive FP64 input raised ZeroDivisionError because its scale underflowed; a one-shot iterable was exhausted during validation. The codec now materializes input and rejects unrepresentable scales/nonfinite reconstruction. This is a narrow-range CPU teaching format, not GPTQ/AWQ/GGUF serialization.
- [A100 80GB SXM specifications](https://www.nvidia.com/en-us/data-center/a100/) give 312 dense FP16 TFLOPS and 2,039 GB/s. The resulting roofline-rate fraction isn't idle time. Code compression doesn't guarantee hidden unpacking, Tensor Core dispatch, fourfold decode speed, or a prefill bottleneck.
- [GPTQ paper](https://arxiv.org/html/2210.17323v2) inspected selections: fixed-input objective, active-set compensation, common column order, lazy batching, Cholesky reformulation, and asymmetric experimental grids. The factor-of-one-half in the lesson follows its explicit H=2XXᵀ convention. Sequential discrete rounding doesn't guarantee a global optimum.
- [Pinned GPTQ code](https://github.com/IST-DASLab/gptq/blob/2d65066eeb06a5c9ff5184d8cebdf33662c67faf/gptq.py) inspected fasterquant: dead columns before damping, damping H before inversion, upper Cholesky UᵀU, local row updates, deferred GEMM, act-order/static groups. NumPy checks the first-step factor identity; the CUDA exporter wasn't run. Act-order measures uncentered energy, not variance.
- [AWQ paper](https://arxiv.org/html/2306.00978v5) inspected selections: activation-selected floating-point exceptions motivate scaling, changed group steps limit protection, exponent search and separate clipping, and experimental scope. Its 1% observation isn't a fixed selection rule or universal accuracy/generalization guarantee.
- [Pinned AWQ code](https://github.com/mit-han-lab/llm-awq/blob/d6e797a42b9ef7778de8ee2352116e0f48a78d61/awq/quantize/auto_scale.py) searches twenty module-level exponents 0 through 0.95, clamps/normalizes scales, and rescales eligible norm or linear parameters. Explicit activation wrappers qualify zero-overhead fusion claims. The four-vector CPU exercise isn't a complete AWQ implementation.
- [Transformers GPTQ guide](https://huggingface.co/docs/transformers/main/en/quantization/gptq) uses GPTQModel and discontinues AutoGPTQ support; asymmetric packing has compatibility restrictions. The [AWQ guide](https://huggingface.co/docs/transformers/main/en/quantization/awq) still describes AutoAWQ dependencies and warnings. [AutoAWQ](https://github.com/casper-hansen/AutoAWQ) was archived May 11, 2025; its last tested Torch/Transformers configuration isn't a current compatibility guarantee. Main documentation isn't the released package version.
- [GGUF specification](https://github.com/ggml-org/ggml/blob/master/docs/gguf.md) inspected metadata, alignment, typed tensors, compatibility, and sharding passages. Alignment defaults to 32; mmap doesn't eliminate disk reads, page faults, GPU transfers, or architecture/backend requirements.
- [Pinned Q4_K layout](https://github.com/ggml-org/llama.cpp/blob/709fe755dfa810d77e2ac386292b29648b536864/ggml/src/ggml-common.h): 128 code bytes + twelve packed scale/minimum bytes + four super-scale bytes = 144 bytes/256 weights. Metadata is exactly 0.5 bits/weight. [Preset selection](https://github.com/ggml-org/llama.cpp/blob/709fe755dfa810d77e2ac386292b29648b536864/src/llama-quant.cpp) includes model-specific mixtures; Q4_K_M isn't a tensor type.
- [Pinned model placement](https://github.com/ggml-org/llama.cpp/blob/709fe755dfa810d77e2ac386292b29648b536864/src/llama-model.cpp) includes the output layer in trailing GPU-layer counting. The matching common/arg.cpp supports -ngl, --gpu-layers, and --n-gpu-layers. A new executable count example and the separate budget example distinguish versioned assignment from a safe allocator configuration.
- The [vLLM cache guide](https://docs.vllm.ai/en/latest/features/quantization/quantized_kvcache/) describes FP8 formats, scaling, and backend restrictions, not generic INT8 cache support. The held-out fixture computes floating-point reconstruction MSE and ideal code bytes only; it doesn't measure packed storage, perplexity, reasoning, bandwidth, or task-safe bit thresholds.

# Manually checked source notes, September 22, 2026

Relevant selections inspected, not complete upstream projects or every paper. CPU examples test arithmetic, routing, and synthetic control flow. No model training/inference, GPU execution, actual network collective, serving benchmark, or deployment was performed.

- [Original sparsely gated MoE](https://arxiv.org/pdf/1701.06538), downloaded PDF v1, abstract and section 2 text: selected feed-forward subnets, weighted sum, and noisy top-k. Original experiments use recurrent backbones; the lesson's modern Transformer explanation also cites Mixtral. PDF text was extracted mechanically; no figure inspection is claimed.
- [Mixtral, HTML v1](https://arxiv.org/html/2401.04088v1), architecture/parameter accounting and routing-analysis selections: FFN-only expert pool, eight/top-two SwiGLU paths, selected-logit softmax, paper-rounded 47B/13B, and specified syntax/locality findings. Counts don't prove identical dense-model latency or universal expert specialties.
- [Switch, HTML v3](https://arxiv.org/html/2101.03961v3), sections 2.1–2.2: retained top-one softmax gate, static capacity/residual overflow, f/P definitions, stop-gradient on hard counts, and coefficient sweep. The lesson's feasible two-token/three-expert calculation gives 0.90 despite one unused expert: the uniform value isn't a general lower bound or coverage certificate for the dot-product expression. This is a direct counterexample, not a training experiment.
- [Expert choice, HTML v2](https://arxiv.org/html/2202.09368v2), method/overview selections: fixed expert buckets and variable per-token coverage. The future-token example is an explicit consequence of bucket-wide selection: causal attention doesn't make that selection prefix-independent. It doesn't claim an observed deployed implementation bug.
- [DeepSeek-V2, HTML v5](https://arxiv.org/html/2405.04434v5), architecture/balancing/setup selections: first FFN dense; 160 routed plus two shared, six routed selections, 236B/21B, three destination devices in the reported configuration, and distinct balancing scopes. Layer counts and widths prevent naive comparisons of active expert counts.
- [DeepSeek-V3, HTML v2](https://arxiv.org/html/2412.19437v2), router/setup/decode selections: first three FFNs dense; 256 routed plus one shared, eight routed selections, 671B/37B; sigmoid affinity, selection-only balancing bias, complementary sequence loss, and TP4/DP80 attention with EP320 decoding. Redundant experts add physical copies without adding new logical expert functions.
- [DeepSeek-V4, HTML v1](https://arxiv.org/html/2606.19348v1), inherited designs and Flash setup: 43 MoE blocks, first three hash-routed, 256 routed plus one shared, six selections, 284B/13B, sqrt(softplus) learned affinity, and removal of routing-node limits. [Flash 0731 card](https://huggingface.co/deepseek-ai/DeepSeek-V4-Flash-0731), introduction: attached DSpark module means the released artifact isn't established by the core-size label alone.
- [GLM family repository](https://github.com/zai-org/GLM-5), introduction/download selections: current GLM-5.3 remains vendor-labelled 744B-A40B and shares the GLM-5.2 base; Flash has a different 320B-A18B hybrid base. [GLM-5.3 card](https://huggingface.co/zai-org/GLM-5.3) confirms the post-training distinction. [Pinned BF16 config](https://huggingface.co/zai-org/GLM-5.3-BF16/blob/304b8051cfb2b260b61ce0cbe330e02a98e73639/config.json), full JSON retrieved: 78 layers, three dense then 75 sparse, 256 routed/one shared/eight selections, sigmoid, norm_topk_prob, and routed_scaling_factor=2.5. No weights loaded or serving behavior measured.
- [GLM-5.3-Flash card](https://huggingface.co/zai-org/GLM-5.3-Flash), introduction: newly trained multimodal sparse/linear hybrid and vendor 320B/18B labels. No benchmark ranking, price comparison, or generic KV-memory estimate imported.
- [Qwen3.6-35B-A3B card](https://huggingface.co/Qwen/Qwen3.6-35B-A3B), architecture list: 35B/3B language-model labels, 40 layers, 256 experts/eight routed plus one shared, and ten groups of three Gated DeltaNet layers followed by gated attention. Expert routing and sequence mixing are separate dimensions.
- [GLU variants](https://arxiv.org/pdf/2002.05202), downloaded v1 PDF sections 1–3 text: SwiGLU has three matrices with matched-size comparisons, not a one-matrix activation or blanket quality guarantee. No PDF figure inspection is claimed.
- [ST-MoE, HTML v2](https://arxiv.org/html/2202.08906v2), noise and z-loss selections: XL input jitter's quality cost and the square of log-sum-exp, not componentwise squared logits or an assignment balance term. The common-offset example keeps softmax unchanged while changing z-loss. Very negative losing logits need not contribute appreciably to the log-partition penalty.
- [Megatron Core MoE guide](https://docs.nvidia.com/megatron-core/developer-guide/latest/user-guide/features/moe.html), dropless/parallelism/functionality selections: capacity-limited dropping isn't universal. Match exact routing group, padding, loss scope, and implementation before copying a coefficient or topology.
- [vLLM expert parallel source guide](https://github.com/vllm-project/vllm/blob/main/docs/serving/expert_parallel_deployment.md), downloaded deployment/layer-behavior/EPLB sections: TP×DP expert ownership, attention-specific layouts, phase-oriented backends, load-driven mapping changes, and redundant-copy memory cost. The docs webpage couldn't be retrieved by the web tool; the official raw source was retrieved and read. No flag recipe was executed. Per-assignment versus token-destination payload counts are separate declared hypothetical protocols, not measured traffic.

Reproduced boolean top_k acceptance, fractional slice TypeError, NaN output weights, and a huge-integer OverflowError in the original tiny router. The revised helper converts/checks finite values, rejects noninteger counts, and rejects invalid projected logits. A cold expert's task-gradient contribution and optimizer updates/weight decay are distinct; tokens aren't individual optimizer steps. Replaced repeated symptom/cause/fix blocks with diagnostic comparisons that don't assert a root cause from one symptom.

# Manual source notes, September 22, 2026

- Read the complete article, six original CPU exercises, ten questions, three native sources, banner TSX/text, and all four downloads. The 553-line CUDA lab implements integer reduction and scan; arg reduction and online softmax are CPU examples, not downloadable GPU implementations. The retained receipt belongs to an older source hash and wasn't independently reproduced.
- [CUDA language extensions](https://docs.nvidia.com/cuda/cuda-programming-guide/05-appendices/cpp-language-extensions.html), shuffle and participant constraints: an absent in-range source yields an undefined result; a down-shuffle beyond the subgroup boundary leaves the caller unchanged. A full mask doesn't recreate exited lanes. Shuffle exchanges aren't shared-memory fences and don't promise one-cycle latency. The legacy 64-bit integer atomicAdd overload is unsigned.
- [Current PTX model](https://docs.nvidia.com/cuda/parallel-thread-execution/index.html), Independent Thread Scheduling: Volta introduced per-thread execution state. Explicit collective participation replaces unsafe implicit warp-synchronous assumptions. Read the relevant model paragraphs, not the entire ISA.
- [Device-callable APIs](https://docs.nvidia.com/cuda/cuda-programming-guide/05-appendices/device-callable-apis.html), grid_group and grid synchronization: cooperative launches can synchronize a supported, appropriately sized grid. Ordinary-launch spin barriers can deadlock. Same-stream ordering doesn't repair intra-kernel races.
- [Original reduction slides](https://developer.download.nvidia.com/compute/cuda/1.1-Beta/x86_website/projects/reduction/doc/reduction.pdf): reused the preceding bundle's inspected multi-pass/multiple-items material. Historical volatile warp-synchronous code isn't a modern synchronization contract. Adjacent accesses don't establish physical HBM transactions or a bandwidth bottleneck.
- [CUB reduction](https://nvidia.github.io/cccl/unstable/cub/api/structcub_1_1DeviceReduce.html) and [CCCL determinism](https://nvidia.github.io/cccl/unstable/cccl/determinism.html): reduction defaults to run_to_run; supported environment APIs request other guarantees. Reproducibility is scoped to fixed library/toolkit/tuning. A fixed tree can repeat despite different block completion order. Wider output alone isn't a full accumulator declaration; the comparison fragment explicitly widens inputs.
- [CUB scan](https://nvidia.github.io/cccl/unstable/cub/api/structcub_1_1DeviceScan.html): default not_guaranteed differs from reduction; supported environment APIs can request run_to_run float addition. Treat current/unstable documentation separately from an installed release. Single-pass useful input/output traffic excludes metadata, initialization, and redundant look-back work.
- [Original look-back report](https://research.nvidia.com/sites/default/files/pubs/2016-03_Single-pass-Parallel-Prefix/nvr-2016-002.pdf), operation/properties/adaptations: X must wait; P is inclusive through its own tile; publication needs visibility ordering and forward progress. Atomic-counter assignment is an adaptation. [Current agent](https://github.com/NVIDIA/cccl/blob/main/cub/cub/agent/agent_scan.cuh) instead assigns start_tile + blockIdx.x in ConsumeRange. Relevant source lines read directly, not the entire upstream project.
- Scan arithmetic derived independently: Hillis-Steele uses n log2(n) - (n-1) additions for power-of-two n; Blelloch uses 2n-2. At n=512 these are 4097 and 1022, ratio 4.01; that isn't a traffic or speed ratio. Added counted examples, flag-to-address compaction, and segmented sums with an empty segment.
- [Online normalizer paper](https://arxiv.org/html/1805.02867v2), Algorithms 2/3 and fusion: maximum/normalizer use one input pass, but standalone complete softmax rereads logits. A tile retained on chip has a different traffic pattern. Rounded denominator displays aren't exact numerical values; finite logits can underflow, and masks/nonfinite/all-masked rows need policies.
- [FlashAttention](https://arxiv.org/abs/2205.14135): reused preceding attention lessons' inspected tiling/storage passages. The displayed accumulator is unnormalized until its final division. Fused weighted-value output avoids storing every probability; it doesn't remove quadratic arithmetic or guarantee compute-bound performance.
- [Floating-point guide](https://docs.nvidia.com/cuda/cuda-programming-guide/05-appendices/mathematical-functions.html): grouping changes rounding and can significantly alter answers. Accuracy and bitwise repeatability require separate contracts; don't dismiss an unexpected failure as non-associativity.
- [CUB overview source](https://github.com/NVIDIA/cccl/blob/main/docs/cub/developer_overview.rst) and [execution environments](https://nvidia.github.io/cccl/unstable/cub/environment.html): block/warp collectives can live inside fused custom kernels. Device-wide two-phase storage queries aren't the only available API pattern. Architecture-specific dispatch isn't a runtime tuning promise; iterators can adapt strides. RoPE's pair rotation isn't itself a reduction.
- [Compute Sanitizer](https://docs.nvidia.com/compute-sanitizer/ComputeSanitizer/): reused the preceding bundle's inspected memcheck/racecheck/synccheck passages. Shared-memory hazards need conflicting writes; a warp barrier doesn't order another warp. Clean reports cover enabled checks on exercised paths, not all schedules or numerical correctness.

[CUDA stream semantics](https://docs.nvidia.com/deeplearning/nccl/user-guide/docs/usage/streams.html): asynchronous execution and completion through CUDA synchronization/events. Current pages identify NCCL 2.31.2. CPU arithmetic/schedules don't execute NCCL.
- [vLLM disaggregated prefill](https://docs.vllm.ai/en/latest/features/disagg_prefill/): experimental feature status and canonical prefill token-ID reuse via kv_transfer_params on chat completions. The messages field is still required; the inspected IDs replace decode-side templating/tokenization. This isn't a universal request format or trust boundary.
- [vLLM KVTransferConfig](https://docs.vllm.ai/en/latest/api/vllm/config/kv_transfer/): current kv_load_failure_policy is fail by default; recompute reschedules failed blocks. These engine-local policies don't implement transparent client stream continuation or service-wide failover.
- [NIXL architecture](https://github.com/ai-dynamo/nixl/blob/main/docs/nixl.md): conductor ownership, memory sections, registration, metadata side channels, buffer descriptors, asynchronous handles, and remote-agent invalidation selections. Platform/runtime policy remains outside a transfer library. No claims about a fixed exhaustive list of released backend capabilities were inferred from the overview.
- [NIXL BackendGuide](https://github.com/ai-dynamo/nixl/blob/main/docs/BackendGuide.md): transfer operations, lack of request ordering/region locking, asynchronous release/abort result distinctions, and UCX initialization-option section. The current peer error-handling default and none option affect lane eligibility and remote-failure visibility. Missing error notification doesn't prove stopped DMA. Inspected the relevant source sections, not every backend implementation.
- [Dynamo development architecture](https://docs.nvidia.com/dynamo/dev/knowledge-base/concepts/system-architecture/disaggregated-serving): returned handoff metadata, backend-specific flow, nonblocking transfer, and prefill/decode pool tradeoffs. [Development router flow](https://docs.nvidia.com/dynamo/dev/knowledge-base/modular-components/router/disaggregated-serving): integrated frontend activation, standalone composition, and failure after prefill dispatch. These dev/beta pages aren't a blanket stable-release compatibility guarantee.
- [Dynamo topology-aware KV transfer](https://docs.nvidia.com/dynamo/dev/knowledge-base/modular-components/router/topology-aware-kv-transfer): experimental status, selected-worker topology, required eligibility versus preferred cost bias, and fail-closed required constraints. Preferred weight isn't a probability or same-domain guarantee. Added its direct reference instead of attaching the detailed claim only to the general router page.
- [Splitwise abstract](https://arxiv.org/abs/2311.18677) and [DistServe abstract](https://arxiv.org/abs/2401.09670): phase separation, separately managed resources/latency objectives, and the need to account for state movement. Reused earlier manual paper mechanism reviews; no newly claimed full-paper read or performance reproduction.
- [Mooncake primary abstract](https://arxiv.org/abs/2407.00079) and [v4 early-rejection sections 7.1–7.4](https://arxiv.org/html/2407.00079v4): KV-centric scheduling, delayed-load oscillation, and system-level future-load prediction under overload. Its paper revision is v4, September 2025. The lesson's destination-reservation sequence is explicitly a local design choice, not a claim that Mooncake implements exactly this protocol. No new whole-paper review or evaluation reproduction was claimed.

## Corrections and teaching decisions

The original 2.50 GiB logical payload, 1.25 GiB ideal per-rank shards, 2,600 MiB rounded reservation, shared versus independent bandwidth arithmetic, and 70 ms overlap example are correct. They assume full per-layer attention KV at the stated dimensions; replication, alternative architectures, pools, and conversion still change real physical accounting.

Corrected the claim that taking the union of active spans suffices for TTFT. Uninstrumented waits can be absent from that union. The new worked case shifts the same overlapped work behind 25 ms of queueing: end-to-end TTFT becomes 400.4 ms while the active-span union stays 375.4 ms. Measure consistently defined endpoint elapsed time, then use joined spans to explain overlap and gaps. Updated the p99 question accordingly; phase percentiles still don't generally add.

Added the group-call boundary before GPU completion and current Dynamo required/preferred routing distinction, integrated versus standalone scope, and failure posture. Added NIXL UCX configuration's loss of peer-failure visibility because a fast transport configuration also changes the evidence required for reclamation.

Reproduced a NaN lease committing at a distant clock tick in the original local lab. Reproduced boolean/floating rank-block labels satisfying integer coverage through Python equality. The lab now rejects invalid clock ticks, durations, byte/count fields, empty manifest identity, and noninteger block identities before mutating ownership/coverage. Its caller supplies trusted destination simulation ticks; the lab doesn't obtain clock, authentication, GPU visibility, or transport quiescence evidence. Kept the 720 serialized interleavings and trusted finish/abort/consumer assumptions explicit.

The generated packet's release-after-retry-window language was incomplete: reclamation also requires stopped physical accesses. Preserved the article's distinction between admission revocation, transport stop, GPU-reader stop, and returned capacity. Neither a higher attempt number nor a successful model check validates a backend's cancellation behavior.

No new production framework commands or benchmark targets were added. The original narrative already distinguishes control decisions, intra-replica collectives, and distinct KV shards, and makes output ownership/cursor uncertainty visible.

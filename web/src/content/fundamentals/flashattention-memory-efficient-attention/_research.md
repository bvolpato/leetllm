# Manual source review: 2026-09-22

- FA1, Algorithm 1 and Theorems 1–2: original loop nest writes intermediate O/m/l to HBM; its saved row statistics are m/l. The two-level IO theorem counts scalar elements, assumes d <= M <= Nd, and does not imply linear IO for fixed M/d.
- FA2, Sections 3.2–3.3 and 4: Q-resident loop nest, unnormalized output, sequence parallelism, and removal of the split-K output reduction. Forward shared-memory reduction is not an atomic-add claim; backward still needs synchronization. Kernel throughput and end-to-end training throughput have different scopes.
- FA3, Section 3.1: producer/consumer buffers and barriers permit overlap rather than guarantee complete overlap. WGMMA uses both shared-memory and register-sourced first operands.
- FA4, Sections 3 and 5: larger asynchronous MMA tiles, software exponentials, conditional reference updates, tensor memory/two-CTA backward. The old reference can be retained only with consistent new weights. B200 results compare specified BF16 kernel workloads; the paper explicitly says later cuDNN versions reached similar performance. CuTe-DSL compiles GPU kernels.
- Current official README: FA4 package/import path and Hopper/Blackwell targets. Current flash_attn_interface.py: FP32 saved LSE, retained Q/K/V/O and RNG state, bottom-right causal alignment; paged flash_attn_with_kvcache requires page sizes divisible by 256 and does not support backward.
- NVIDIA H100 specifications: 1,979 TFLOPs/s FP16/BF16 is sparsity-rated; illustrative dense peak is half. Hopper tuning guide separates per-SM shared-memory and register budgets and documents cluster memory and TMA synchronization.
- PyTorch 2.14 SDPA docs: FP32 math intermediates for FP16/BF16, mask polarity/alignment, dropout behavior, restricted backend selection and numerical differences. Transformers attention-backend docs confirm named FA2/FA3 requests and Hub-kernel loading; those requests do not establish FA4 dispatch.
- Manual arithmetic: four baseline intermediate passes total 128 GiB; one saved 32 GiB P matrix costs 64 GiB for a write/read pair. The 4,096x comparison is P versus LSE, not total activations. Equal square causal tiles skip 37.5% of pairs in the four-tile example, approaching 50% of tile work rather than a measured traffic/time saving.
- Added CPU examples for the roofline rate/idle-cycle distinction, absolute-position tile classification, and accumulator overflow. The overflow example failed before the guard with `AssertionError: silent overflow accepted`; the dense normalized result was finite. The sketch now rejects nonfinite accumulated state, rather than claiming robust FP64 arithmetic for every finite input.

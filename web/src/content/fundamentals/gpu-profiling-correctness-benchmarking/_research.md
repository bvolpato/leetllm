# Correct GPU Profiling and Benchmarking

Manual primary-source refresh: September 22, 2026. The triad CUDA lab was read in full but wasn't compiled or executed on CUDA. Its expected output is an acceptance shape. The marked Python exercises use CPU execution and synthetic timings, not GPU performance results.

- [CUDA API synchronization behavior](https://docs.nvidia.com/cuda/cuda-runtime-api/api-sync-behavior.html): kernel launches are asynchronous with respect to the host, but any API can block for internal resources or contention. Remove fixed 2–5 microsecond submission claims and the assertion that the GPU cannot have started when the call returns.
- [Current CUDA event management](https://docs.nvidia.com/cuda/cuda-runtime-api/cuda_runtime_api/group__CUDART__EVENT.html): the old URL without the extra `cuda_runtime_api/` segment returns HTTP 404. Events capture stream work, elapsed time has roughly 0.5-microsecond resolution, and interleaved work can increase the interval. Event timing isn't pure instruction time or every queue delay. [Device management](https://docs.nvidia.com/cuda/cuda-runtime-api/cuda_runtime_api/group__CUDART__DEVICE.html) defines the completion wait for preceding work.
- [Floating-point guidance](https://docs.nvidia.com/cuda/floating-point/index.html) and [PyTorch allclose](https://docs.pytorch.org/docs/stable/generated/torch.allclose): explain FMA rounding and the reference-relative tolerance expression. The lab's double FMA followed by a float cast is useful independent evidence, not a universal bitwise oracle. Its frozen tolerances apply to its stated triad workload, not arbitrary reductions.
- [Compute Sanitizer](https://docs.nvidia.com/compute-sanitizer/ComputeSanitizer/): the four tools check distinct classes of errors. Padding adds separation after supported global allocations; it doesn't expose a logical overrun still inside an oversized allocation. Racecheck isn't an all-memory race detector. Standalone launches are nonblocking by default, so remove the claim that sanitizers necessarily serialize all warps. Clean reports support tested executions, not all-input safety proofs.
- [Nsight Systems guide](https://docs.nvidia.com/nsight-systems/UserGuide/): enabled tracing, memory tracking, and backtraces can substantially perturb execution. Remove the unsupported universal 1–5% overhead estimate. Use the timeline for the declared critical path, then collect clean timing separately.
- [Nsight Compute profiling guide](https://docs.nvidia.com/nsight-compute/ProfilingGuide/): metric count and hardware determine replay passes. Kernel replay saves accessed memory and restores the written subset for later passes; single-pass collection can avoid this work. Normally serialized kernel launches don't imply serialized warp scheduling or memory-controller queues. Range replay differs. Default cache flushing and replay can change the application's residency state.
- [Nsight Compute CLI](https://docs.nvidia.com/nsight-compute/NsightComputeCli/): record selected sections, replay, cache, and clock controls. Traffic counters from a cache-flushed profile cannot be paired with a hot benchmark's duration to invent a Roofline point.
- [Hopper tuning guide](https://docs.nvidia.com/cuda/hopper-tuning-guide/index.html): H100's nominal L2 is 50 MB. Three lab buffers occupy 12,000,036 bytes, approximately 11.44 MiB. Fit doesn't prove residency. Remove the unsupported B200 cache figure, H100 12 TB/s claim, and guaranteed all-line hits. Rotation and a separate sweep encourage turnover without proving every useful byte reached HBM. Match the intended application path, which can legitimately retain cache reuse.
- [nvidia-smi](https://docs.nvidia.com/deploy/nvidia-smi/index.html): select the GPU explicitly; requested SM clock locks are hardware-dependent and don't prevent thermal/power reductions or fix memory clocks. Reset restores defaults rather than the previous custom policy. Observe actual state. ABBA balances order but doesn't prevent drift or diagnose its cause.

The receipt exercise now validates positive integer element counts, the lab dtype, consistent buffer policy/slot counts, and nonempty device/timer labels before equality and CSV checks. A before/after CPU probe demonstrated the original boolean-count bug. Hashes bind files to saved bytes; they don't authenticate GPU origin, correctness, cache residency, or independent rounds.

# Manual accelerator-guide source review, September 22, 2026

The published lesson follows one illustrative BF16 projection through prefill and decode. Shape calculations and service thresholds are exercises, not vendor benchmarks. Selected architectures don't imply that each is its vendor's newest product.

- H100 SXM's product table specifies 80 GB and 3.35 TB/s; the older tuning summary says up to 3 TB/s. H100 NVL is a different PCIe SKU. Register capacity, per-block shared memory, chip-wide L2, and HBM aren't one interchangeable pool. Removed unsupported cross-vendor cache-bandwidth and cycle-latency ranges. [Product specifications](https://www.nvidia.com/en-us/data-center/h100/), [Hopper tuning](https://docs.nvidia.com/cuda/archive/13.0.0/hopper-tuning-guide/index.html).
- Arithmetic intensity identifies the larger term of a stated roofline. It doesn't establish peak execution, stall cycles, or chip idle time. The native figure now uses the same hypothetical 200 FLOP/byte balance as the CPU example and calls M=8 a small GEMM. No GPU timing was performed. [Original Roofline paper](https://doi.org/10.1145/1498765.1498785).
- Partial host offload needs a fraction, rate, and overlap model. Removed the claim that any fraction guarantees over 98% waiting. Dense weights are reused across batched rows; MoE expert selection changes traffic. The CPU fixture explicitly assumes sequential cold reads and a rounded 64 GB/s host path, excluding computation and KV traffic.
- SIMT thread execution and systolic matrix dataflow describe different layers of a machine. Hopper WGMMA has shared-memory/register operand variants and register accumulators; it doesn't erase register pressure. The original TPU's systolic diagram is historical, not a v6e geometry specification. Removed the claim that eight rows prove 93% chip idle time or that GPU scalar work leaves no silicon idle. [PTX ISA](https://docs.nvidia.com/cuda/parallel-thread-execution/), [Google's original TPU explanation](https://cloud.google.com/blog/products/ai-machine-learning/an-in-depth-look-at-googles-first-tensor-processing-unit-tpu), [NeuronCore-v3 engines](https://awsdocs-neuron.readthedocs-hosted.com/en/v2.29.1/about-neuron/arch/neuron-hardware/neuron-core-v3.html).
- The pinned ROCm 7.14 hardware table maps MI300 to CDNA 3/gfx942 and MI350 to CDNA 4/gfx950. HIP's documented CDNA wavefront width is 64. RCCL's MI300X usage section confirms dedicated pair links in its documented eight-GPU system. These facts aren't a recommendation to install the pinned version on arbitrary hardware. [Release table](https://rocm.docs.amd.com/en/docs-7.14.0/about/release-notes.html), [HIP model](https://rocm.docs.amd.com/projects/HIP/en/develop/understand/programming_model.html), [RCCL usage](https://rocm.docs.amd.com/projects/rccl/en/docs-7.2.4/how-to/rccl-usage-tips.html).
- v6e has one TensorCore with two MXUs, plus vector and scalar resources. Pallas documents generally sequential lexicographic grids, consecutive input-slice reuse, and consecutive writes to a shared output slice; multicore configurations are an exception to the simple execution description. The tile-order fixture is a small traffic model, not a legal kernel or timing simulation. [v6e](https://docs.cloud.google.com/tpu/docs/v6e), [Pallas TPU details](https://docs.jax.dev/en/latest/pallas/tpu/details.html).
- Trainium's documented SBUF/PSUM live-set overflow can cause compiler spills to the next tier. Trn2's sixteen chips use a 4x4 torus; a four-instance UltraServer adds rings between corresponding chip coordinates. Removed the prior research's unsupported bandwidth and memory-pooling simplifications. [NKI memory hierarchy](https://awsdocs-neuron.readthedocs-hosted.com/en/v2.32.0/nki/get-started/about/memory-hierarchy-overview.html), [Trn2 topology](https://awsdocs-neuron.readthedocs-hosted.com/en/v2.32.0/about-neuron/arch/neuron-hardware/trn2-arch.html).
- PyTorch MPS targets GPU execution; MPS Graph's broader platform API doesn't imply that PyTorch automatically uses the Neural Engine. Unified memory remains finite. Operator fallback doesn't fix unsupported float64 tensor allocation. Stable-document redirects were followed to PyTorch 2.14, and complete upstream Markdown pages were read after initial RST guesses returned 404. No Mac/backend execution was performed. [Apple PyTorch guide](https://developer.apple.com/metal/pytorch/), [MPS Graph](https://developer.apple.com/documentation/metalperformanceshadersgraph), [PyTorch MPS](https://docs.pytorch.org/docs/2.14/notes/mps.html), [Fallback configuration](https://docs.pytorch.org/docs/2.14/mps_environment_variables.html), [MLX memory model](https://github.com/ml-explore/mlx).
- TP can cross nodes, and a fast fabric can span a rack. Removed fixed collective microsecond promises and the claim that EP communicates only once per complete forward pass. A classic dense TP reduction count isn't a universal hybrid/MoE contract. The 128 KiB tensor is logical payload; ring transmitted bytes have a group-size factor. [vLLM serving guidance](https://docs.vllm.ai/en/latest/serving/parallelism_scaling.html), [HGX specifications](https://docs.nvidia.com/enterprise-reference-architectures/hgx-ai-factory-h100-h200-b200/latest/components.html), [GB200 NVL72](https://www.nvidia.com/en-us/data-center/gb200-nvl72/), [NCCL bandwidth conventions](https://github.com/NVIDIA/nccl-tests/blob/master/doc/PERFORMANCE.md).
- Defined numerical and task-quality tolerances replace automatic rejection for any rounding drift. Memory fit is per-device and includes reserved pools once; a universal 10-15% reserve doesn't guarantee OOM avoidance. A twenty-request CPU trace demonstrates 95% marginal pass rates with only 90% joint compliance. Cost uses the same observation interval as eligible output and avoids double counting rented hardware's capital expense.
- The old generated research's unsupported M4 Ultra example, unsourced late-2026 precision comparisons, stale newest-product framing, and implied timing predictions were removed. Actual hardware selection requires measured correctness, fit, latency, and useful output under the intended workload. Blackwell compatibility still needs attention to architecture-conditional PTX. [Blackwell compatibility](https://docs.nvidia.com/cuda/blackwell-compatibility-guide/).

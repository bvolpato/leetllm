# Manual source notes, September 22, 2026

- [NVCC 13.4](https://docs.nvidia.com/cuda/cuda-compiler-driver-nvcc/) documents phases, source separation, packaging, target compatibility, and register-cap ABI limits. Internal subcommands/IR aren't stable build interfaces.
- [NVVM IR 13.4](https://docs.nvidia.com/cuda/nvvm-ir-spec/) describes IR 2.0 and two LLVM dialects. The modern LLVM 22.1 dialect targets Blackwell and later. Legal LLVM IR isn't automatically valid NVVM IR; this isn't a promise that nvcc emits a readable NVVM file.
- [libNVVM](https://docs.nvidia.com/cuda/libnvvm-api/) compiles supported NVVM modules to PTX or LTO IR. [Binary Utilities](https://docs.nvidia.com/cuda/cuda-binary-utilities/) describes actual cubin resource reporting and nvdisasm liveness. Cubins contain native code; SASS is a disassembly, not architecture microcode. A fatbin is a device-image container, not a standalone host executable.
- [PTX 9.4](https://docs.nvidia.com/cuda/parallel-thread-execution/) distinguishes virtual registers from physical allocation and target feature sets. Baseline cp.async.bulk requires sm_90; Hopper WGMMA requires sm_90a. Enabled features don't establish their use by a particular kernel.
- [Hopper](https://docs.nvidia.com/cuda/hopper-tuning-guide/index.html), [Ada](https://docs.nvidia.com/cuda/ada-tuning-guide/index.html), and [Blackwell](https://docs.nvidia.com/cuda/blackwell-tuning-guide/index.html) have different warp/shared-memory/block limits. Ada 8.9 and Blackwell 12.0 allow 48 resident warps, Hopper 9.0 and Blackwell 10.0 allow 64. The article's rounded register puzzle is explicitly a simplified model, not a hardware occupancy table.
- [Language extensions](https://docs.nvidia.com/cuda/cuda-programming-guide/05-appendices/cpp-language-extensions.html) describes launch bounds and register qualifiers. Constraints can change instructions/spills; minimum-block hints don't override shared-memory limits. [Shared spilling's authored explanation](https://developer.nvidia.com/blog/how-to-improve-cuda-kernel-performance-with-shared-memory-register-spilling/) dates to August 27, 2025 and CUDA 13.0. Whole-program/static-memory restrictions apply. Launch bounds are recommended; the AI summary incorrectly makes them mandatory.
- [NVRTC 13.4](https://docs.nvidia.com/cuda/nvrtc/) currently emits Tile IR, not Tile cubins, for Tile compilation. [nvJitLink](https://docs.nvidia.com/cuda/nvjitlink/) links supported GPU device-code inputs to cubin. [CUDA environment variables](https://docs.nvidia.com/cuda/cuda-programming-guide/05-appendices/environment-variables.html) control forced/disabled PTX JIT, compute caching, and lazy/eager loading. Packaging checks need fresh processes and compatible targets.
- [Triton's pinned NVIDIA backend](https://github.com/triton-lang/triton/blob/ee07f7ff302740dbb858b84c7c1ea9f1d1ffc782/third_party/nvidia/backend/compiler.py) supplies TTIR/TTGIR/LLVM/PTX/cubin stages, target-dependent pipelining/layout passes, shared allocation in LLVM lowering, and an actual ptxas subprocess. It isn't the driver's PTX JIT. Swizzles, wide loads, and overlap are conditional outcomes, not blanket performance guarantees.
- [Triton's pinned cache](https://github.com/triton-lang/triton/blob/ee07f7ff302740dbb858b84c7c1ea9f1d1ffc782/python/triton/runtime/cache.py) uses unique PID/UUID temporary writes and os.replace. FileCacheManager.put has no fsync or acquired compilation lock; lock_path alone doesn't prove synchronization. Group records check child-file existence. Atomic visibility isn't power-loss durability or a multi-artifact transaction. Simultaneous misses don't prove corrupt publication.
- [Triton's programming guide](https://triton-lang.org/main/programming-guide/chapter-1/introduction.html) and [vector-add tutorial](https://triton-lang.org/main/getting-started/tutorials/01-vector-add.html) establish blocked program ownership and masked address calculations. [Repository compatibility](https://github.com/triton-lang/triton) lists Linux, NVIDIA compute capability 8.0+, and AMD ROCm 6.2+ for the current project snapshot; installed releases need separate checks.
- [CUTLASS/CuTe](https://docs.nvidia.com/cutlass/latest/overview.html) provides C++ layouts/hardware atoms and Python CuTe DSL. Release-specific features and inspection dependencies differ. The overview mixes historical compatibility text with newer release notes; don't infer all APIs' support from its general minimum-toolkit paragraph.
- [CUDA Tile's 13.4 guide](https://docs.nvidia.com/cuda/cuda-programming-guide/02-basics/writing-tile-kernels.html) documents cuda.tile, CUDA Tile C++ from 13.3, immutable tile values, compiler-owned threads, and compile-time power-of-two dimensions.
- [Pallas](https://docs.jax.dev/en/latest/pallas/) shares Ref/BlockSpec ideas across distinct GPU/TPU APIs. [JAX 0.11.2 changes](https://docs.jax.dev/en/latest/pallas/CHANGELOG.html), released September 17, removed Mosaic GPU pallas_call support, requiring its kernel API, and removed pl.dot. The older Triton backend remains deprecated. Transformation support isn't automatic.
- [NKI](https://awsdocs-neuron.readthedocs-hosted.com/en/latest/nki/get-started/about/index.html) documents Trainium/Inferentia2, Trainium2, and Trainium3, with nki.language and nki.isa control. It isn't a CUDA or TPU portability layer. Memory/engine constraints depend on the NeuronDevice generation.
- CUDA's old n+255 ceiling-division expression has signed overflow at INT_MAX. Quotient-plus-remainder avoids it; the CPU model checks the padded launch count without allocating billions of elements. Small GPU shape checks aren't large-grid validation.
- Manual review covered the complete article, all metadata/questions/reference records, native source, and banner. Primary passages and pinned source selections were inspected, not every upstream project in full. No CUDA/Triton GPU compilation, hardware execution, profiler collection, distributed barrier, filesystem race, or device loading was performed.

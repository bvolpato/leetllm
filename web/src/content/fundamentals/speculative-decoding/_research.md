# Manually checked source notes, September 22, 2026

Relevant selections inspected for this bundle, not complete upstream projects or every paper. The numerical examples are explicit CPU probability/state worksheets; no target/draft model or serving engine was run.

- [Leviathan et al., HTML v1](https://arxiv.org/html/2211.17192v1), section 2/Algorithm 1 and section 3.1–3.3: actual transformed conditional probabilities, ordered acceptance, positive residual, K+1 rows/bonus, simplifying acceptance assumptions, and normalized sequential draft cost. An overall mean acceptance rate is insufficient for the geometric yield formula.
- [Chen et al., HTML v1](https://arxiv.org/html/2302.01318v1), Algorithm 2 and section 4.1: K+1 target distributions, bonus/correction, and conditions under which short scoring blocks stay close to serial decode latency. Weight, cache, collective, kernel, and sampling costs cannot be inferred from parameter count alone. The paper uses opposite p/q labels from this lesson; the lesson consistently uses p for target.
- [H100 specifications](https://www.nvidia.com/en-us/data-center/h100/), product table/footnote: SXM 80 GB, 3.35 TB/s, and 1,979 BF16 TFLOP/s with sparsity. About 989.5 dense TFLOP/s is the applicable peak for the dense worksheet. Use a hypothetical 60 GB active matrix-weight stream rather than imply a 140 GB model fits one 80 GB device. A roofline rate ratio is not measured idle time.
- [Medusa, HTML v3](https://arxiv.org/html/2401.10774v3), sections 2.1–2.3: tree scoring, Medusa-1 frozen backbone versus Medusa-2 joint training, and typical acceptance that relaxes stochastic distribution matching. Tree self/ancestor visibility does not prove arbitrary longest-path sampling exact. The paper's claim that identical draft/target probabilities may still be rejected conflicts with the classic exact sampler; do not repeat it.
- [Original EAGLE, HTML v3](https://arxiv.org/html/2401.15077v3), abstract/section 1: features immediately before the LM head, token sequence advanced one step, and resulting token proposals. Do not misidentify second-to-top-layer features as necessarily an earlier transformer block.
- [EAGLE-2, HTML v1](https://arxiv.org/html/2406.16858v1), abstract/section 1: context-dependent draft trees, confidence-guided expansion/reranking, and unchanged target weights/exact acceptance. It did not introduce the first tree verification architecture.
- [EAGLE-3, HTML v3](https://arxiv.org/html/2503.01840v3), introduction/method and section 4.3/Table 3: removes feature prediction, directly trains tokens with fused layers and simulated multi-step drafting. Historical SGLang v0.4.4, one H100, LLaMA-Instruct 3.1 8B, MT-Bench, length-three chain without trees gives 1.38x throughput at batch size 64; original EAGLE gives 0.99x. This refutes a universal B>=32 slowdown, not establishes a current engine ranking. Avoid its separate vLLM table's conflicting GPU labels.
- [vLLM speculation guide](https://docs.vllm.ai/en/latest/features/speculative_decoding/), schema/TLI/losslessness sections: heterogeneous vocabulary mapping constrains shared token events and currently supports greedy drafting only. Same seed need not yield identical text; finite-precision and batch-dependent logprob differences remain. Inspect installed feature compatibility rather than universalize historical version warnings.
- [vLLM n-grams](https://docs.vllm.ai/en/latest/features/speculative_decoding/n_gram/): prompt matching without another neural model, not zero search/verification memory or compute.
- [vLLM MTP](https://docs.vllm.ai/en/latest/features/speculative_decoding/mtp/): model-family support and Gemma assistant checkpoints using a distinct MTP path. Generic native-MTP descriptions do not cover every assistant checkpoint's storage/state arrangement.
- [vLLM parallel drafts](https://docs.vllm.ai/en/latest/features/speculative_decoding/parallel_draft_model/): trained PARD checkpoints and parallel_drafting configuration, not K ordinary sequential draft calls.
- [SGLang speculation](https://docs.sglang.io/docs/advanced_features/speculative_decoding), relevant EAGLE/MTP/DFlash/standalone/n-gram passages: method-specific draft depth, branching, verification capacity, trained checkpoint support, and scheduler/backend restrictions. N-gram generated-text caches differ from prompt-only lookup. DFlash documents linear block verification. No inference-engine configuration was executed.

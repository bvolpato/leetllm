# Local LLM Deployment: manually inspected source notes

Reviewed September 22, 2026. These are editorial notes for this bundle, not a generated outline or a substitute for reading the article and its assets.

- [Gemma 4 model card](https://ai.google.dev/gemma/docs/core/model_card_4): 12B Unified is listed at 11.95B parameters. Parameter payload arithmetic does not establish downloaded or loaded memory.
- [Ollama Gemma variants](https://ollama.com/library/gemma4/tags) and [12B artifact details](https://ollama.com/library/gemma4:12b): mutable listing shows 7.6 GB, Q4_K_M model data, and BF16 projector. No inference benchmark was run.
- [Pinned Gemma configuration](https://huggingface.co/google/gemma-4-12B/blob/023679ed352de9bb66cc873c9009ce3482585c08/config.json): 40 sliding layers, eight full layers, different KV-head counts/widths, window 1024, shared global K/V projection, and no cross-layer KV sharing. Model dtype is not runtime cache dtype.
- [Pinned Transformers attention/cache implementation](https://github.com/huggingface/transformers/blob/2c4914fb939fe9de0d8e7a798af4684d552f18b4/src/transformers/models/gemma4_unified/modeling_gemma4_unified.py): key normalization/RoPE and value normalization are separate, and both states reach cache.update. Projection sharing does not justify halving this two-array worksheet.
- [NVIDIA Ada whitepaper](https://images.nvidia.com/aem-dam/Solutions/geforce/ada/nvidia-ada-gpu-architecture.pdf): relevant specifications show RTX 4090 24 GB, 384-bit interface, 1008 GB/s peak. This is a named hardware example, not today's flagship or measured token throughput.
- [Mac Studio specifications](https://www.apple.com/mac-studio/specs/): current M5 Max variants list 460/614 GB/s and memory up to 128 GB; M5 Ultra lists 1.2 TB/s and configurations up to 512 GB. Neither peak bandwidth nor installed memory guarantees a model workload fits.
- [MLX repository](https://github.com/ml-explore/mlx) and [unified-memory documentation](https://ml-explore.github.io/mlx/build/html/usage/unified_memory.html): supported CPU/GPU execution shares arrays with scheduled dependencies. MLX does not expose the Neural Engine device. No universal relative runner speed claim is supported here.
- [Pinned llama.cpp placement](https://github.com/ggml-org/llama.cpp/blob/709fe755dfa810d77e2ac386292b29648b536864/src/llama-model.cpp): trailing GPU count includes the output slot. Equal-block capacity arithmetic is not an exact version-independent -ngl setting; actual overrides/allocations need logs.
- [Pinned CLI arguments](https://github.com/ggml-org/llama.cpp/blob/709fe755dfa810d77e2ac386292b29648b536864/common/arg.cpp): accepted cache types include specified float/GGML quantized types, not generic FP8. Installed-version/backend restrictions apply.
- [CUDA allocation contract](https://docs.nvidia.com/cuda/cuda-runtime-api/cuda_runtime_api/group__CUDART__MEMORY.html) and [unified/system-memory guide](https://docs.nvidia.com/cuda/cuda-programming-guide/02-basics/understanding-memory.html): device allocation failure differs from explicit offload, mapped memory, and supported managed/HMM/ATS migration. No automatic ordinary-device oversubscription guarantee.
- [GGUF specification](https://github.com/ggml-org/ggml/blob/master/docs/gguf.md): metadata/tensor container, including sharding. Mapping a file does not establish physical residency or instantaneous startup; file-backed rereads differ from anonymous swap.
- [Ollama import](https://docs.ollama.com/import): supported Safetensors/GGUF inputs; Modelfile is configuration. [API compatibility](https://docs.ollama.com/api/openai-compatibility) explicitly describes a subset, so base-URL replacement is not full behavioral equivalence.
- [Ollama FAQ](https://docs.ollama.com/faq): placement summary, parallel/queue controls, cloud-feature disablement, loopback default, cache types, and platform-dependent behavior. OLLAMA_NO_CLOUD disables cloud features, not all registry/network/telemetry activity.
- [Authentication](https://docs.ollama.com/api/authentication): unauthenticated local API can still invoke signed-in cloud models. Localhost access is not a caller identity or an air gap.
- [Running models](https://docs.ollama.com/api/ps): reported size/size_vram/digest/context are inspection data, not inference-readiness or peak-memory guarantees.
- [Generate contract](https://docs.ollama.com/api/generate) and [usage metrics](https://docs.ollama.com/api/usage): current cached prompt counts and uncached-prompt duration require matching numerator/denominator. Timings are nanoseconds; final streaming chunk carries usage. Missing/zero durations cannot justify fabricated rates. Non-streaming JSON gives no client TTFT/token-gap trace.
- [vLLM repository](https://github.com/vllm-project/vllm): serving features do not select a runtime solely from user count. Reused the preceding manually reviewed PagedAttention and scheduling lessons; token blocks are not OS pages, and fragmentation percentages are workload-specific.
- [HHS cloud guidance](https://www.hhs.gov/hipaa/for-professionals/special-topics/health-information-technology/cloud-computing/index.html) and [EDPB international transfers](https://www.edpb.europa.eu/topics/international-transfers-and-international-cooperation_en): neither law is a blanket cloud/geographic prohibition. Local hosting itself does not establish compliance. Removed categorical export-control claims rather than making a deployment-specific legal determination.

The memory, serial-transfer, timing, and paired-outcome examples are CPU arithmetic/synthetic fixtures. No actual model inference, GPU placement, migration trace, security boundary test, latency benchmark, or deployment is claimed. Relevant source selections were read, not complete upstream projects.
